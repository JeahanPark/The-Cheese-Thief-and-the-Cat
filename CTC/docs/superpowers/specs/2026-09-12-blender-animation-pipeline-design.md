# 블렌더 애니메이션 파이프라인 — 설계

작성 2026-09-12 · 상태: 승인 대기

> 이 문서는 **동작을 어떻게 만드는가**만 정한다. **무엇을 만드는가**(어느 테크에 어떤 동작을
> 붙일지)는 범위 밖이고, 이 파이프라인이 초록이 된 뒤 별도 스펙으로 정한다.

---

## 1. 왜 블렌더인가

솔직하게 적는다. **오늘 필요한 것만 보면 유니티 Animation 창으로 충분하다.** 뼈가 11개,
클립이 10프레임이라 어니언 스킨도 IK도 발 고정도 쓸 일이 없고, 유니티 쪽은 **리그가 이미
붙어 있어 뼈 이름이 틀어질 위험이 아예 없다**(3절의 위험 셋이 통째로 사라진다).

그럼에도 블렌더로 가는 이유는 **천장**이다. 유니티 Animation 창이 영영 못 하는 것이 있다.

| | 유니티 Animation 창 | 블렌더 |
|---|:--:|:--:|
| 있는 리그에 키 찍기 | ○ | ○ |
| 곡선 다듬기·어니언 스킨·IK | ✕ | ○ |
| **새 메시·새 리그** | **✕** | ○ |
| **모델 수정·리타깃** | **✕** | ○ |

지금 제약(「새 프리팹 0 · VFX 0」)은 **취향이 아니라 예산**이다. 블렌더를 한 번 세우면 그
예산선 자체가 올라간다 — 이건 클립 몇 개의 값이 아니라 **앞으로 만들 수 있는 것의 값**이다.

**대가는 정직하게: 설치 + 왕복 시험 하루.** 그 하루가 이 문서의 대부분이다.

## 2. 잰 것

추측이 아니라 파일에서 읽은 값이다.

| 사실 | 출처 | 이것이 정하는 것 |
|---|---|---|
| 리그가 **Generic** (`animationType: 2`) | `Mouse_LOD0.fbx.meta` · `Mouse_Animations.fbx.meta` | 휴머노이드 리타깃이 없다 → **경로와 이름으로만 붙는다.** 한 글자만 달라도 죽는다 |
| 팩이 **뼈/동작 분리 구조** | `Models/Mouse_LOD0.fbx` (메시+리그) · `Animations/Mouse_Animations.fbx` (클립 20, 메시 없음) | **새 클립 = 옆에 FBX 하나 더.** 기존 에셋을 안 건드린다 |
| 클립 20개가 **전부 0~10프레임** | `Mouse_Animations.fbx.meta`의 `firstFrame`/`lastFrame` | 집안 스타일이 **0.33초**다. 새 클립도 이 예산을 지킨다 |
| 본 11개 | 아래 계층 | 손으로도 빠르다 |
| `Shapekey` 레이어 20클립 **전부 미사용** | `AC_Mouse.controller` (스테이트 머신 2개) | 얼굴은 **몸 위에 겹쳐** 돌릴 여지가 남아 있다 (범위 밖, 기록만) |

### 뼈 계층 — 클립이 실제로 붙는 경로

```
Mouse            ← Animator · LODGroup       (PlayerMouse.prefab에서 "Model"로 이름이 바뀐다)
├ Mesh_LOD0..3   ← SkinnedMeshRenderer
└ Rig
  └ root
    └ body
      ├ head
      │ ├ ear.R
      │ └ ear.L
      ├ leg.F.L · leg.F.R · leg.B.L · leg.B.R
      └ tail.01
        └ tail.02
```

커브 경로는 **Animator 기준**이라 `Rig/root/body/head/ear.L` 꼴이다. `PlayerMouse`는
이 프리팹의 변종이고 Animator가 자식(`Model`)에 있으므로 **`Model/` 접두는 붙지 않는다.**

> 고양이(`Cat_LOD0` · `AC_Cat`)도 같은 구조다. 쥐로 먼저 뚫고 고양이는 같은 절차를 되풀이한다.

## 3. 조용히 깨지는 것 셋

블렌더 → 유니티 FBX 왕복의 알려진 실패다. **셋 다 에러도 경고도 없고, 증상은 "그냥 안
움직인다" 하나뿐이다** — 그래서 창작물로 처음 만나면 원인이 안 보인다.

| # | 무엇 | 왜 우리에게 치명적인가 | 막는 법 |
|---|---|---|---|
| 1 | 블렌더가 뼈 이름을 **`아마추어이름 + 뼈이름`**으로 바꿔 쓴다 | Generic은 **이름으로만** 맞춘다. `root`가 `Rig_root`가 되는 순간 11개 전부 어긋난다 | 블렌더의 아마추어 오브젝트 이름을 **정확히 `Rig`**로 둔다. 왕복 시험이 확인한다 |
| 2 | 계층에 **Armature 오브젝트가 한 겹** 끼어든다 | 휴머노이드는 견디지만 **Generic은 깨진다**. 경로가 한 칸씩 밀린다 | 위와 같다 — 우리 계층엔 이미 `Rig`라는 그 한 겹이 있다. **새로 만들지 말고 그 자리에 앉힌다** |
| 3 | **Add Leaf Bones**가 기본 켜짐이라 없던 말단 뼈가 생긴다 | 커브가 딸려 오고 리타깃 도구를 헷갈리게 한다 | 내보내기에서 **끈다** |

추가로, 맨 위가 Null 본이면 유니티가 리그로 인식하지 않는다(스킨드 메시가 붙어 있어야 한다).
동작 전용 FBX는 메시가 없으므로 **아바타를 어디서 가져오는지**가 문제가 된다 → 5절.

## 4. 파일 배치

| | 경로 | 비고 |
|---|---|---|
| 작업 파일 | `art/blender/mouse.blend` · `cat.blend` | **`Assets/` 밖** |
| 산출물 | `Assets/Animations/Pets/CTC_Mouse_Clips.fbx` | 동작만, 메시 없음 |
| 내보내기 스크립트 | `tools/blender/export_clips.py` | 5절 |

**`.blend`를 `Assets/` 안에 두지 않는다.** 유니티는 `.blend`를 발견하면 **블렌더를 직접
실행해** FBX로 변환한다. 그 순간부터 **블렌더가 안 깔린 기계에서는 프로젝트가 열리지
않는다** — CI·다른 사람·빌드 머신 전부. FBX를 커밋하면 그 의존이 생기지 않는다.

`art/`는 새 최상위 폴더다. 유니티가 무시하고, git이 추적한다.

## 5. 내보내기 설정

블렌더 **5.2.1 LTS**를 쓴다.

```
winget install BlenderFoundation.Blender
```

> **2026-09-12 정정.** 처음엔 4.5 LTS로 적었다 — 웹 자료가 그걸 「현재 LTS」라고 해서다.
> 실제로 깔아 보니 **5.2.1이 LTS다**(2026-08-25 빌드). 4.5는 지난 LTS다.
>
> 버전을 올리기 전에 파이썬 API가 그대로인지 **쟀다**(`bpy.ops...get_rna_type()`):
> 내보내기 42개 인자 중 아래 표가 쓰는 **19개가 전부 있고**, 가져오기의
> `ignore_leaf_bones`·`automatic_bone_orientation`도 있다. 스크립트를 고칠 필요가 없다.

FBX 내보내기:

| 항목 | 값 | 이유 |
|---|---|---|
| Forward / Up | `-Z Forward` / `Y Up` | 블렌더는 Z-up 오른손, 유니티는 Y-up 왼손 |
| Scale | `1.0` · **Apply Unit 켬** | 단위를 FBX에 구워 넣는다 |
| Apply Scalings | `FBX All` | |
| **Add Leaf Bones** | **끔** | 위험 3 |
| **Only Deform Bones** | **켬** | 유니티가 원하는 뼈대만 나간다 |
| Primary / Secondary Bone Axis | `Y` / `X` | |
| Sampling Rate | `1` | |
| Bake Animation · Key All Bones · NLA Strips · All Actions | 켬 | |
| 클립 구성 | **동작 1개 = Action 1개** | 유니티에서 클립 하나로 떨어진다 |
| Path Mode | — | 메시·텍스처가 없으므로 해당 없음 |

유니티 쪽 임포트 설정은 **팩의 `Mouse_Animations.fbx`와 똑같이 맞추는 것에서 출발한다**
(`animationType: 2`, `avatarSetup: 1`). 왕복 시험에서 아바타가 안 잡히면 —3절 말미의 Null
본 문제— **Copy From Other Avatar**로 바꿔 `Mouse_LOD0`의 아바타를 가리킨다. 어느 쪽이
맞는지는 **시험이 정한다. 미리 고르지 않는다.**

내보내기는 GUI 버튼이 아니라 **스크립트**로 한다:

```
blender -b art/blender/mouse.blend -P tools/blender/export_clips.py
```

설정이 코드에 있어야 git에 남고, 다음 사람이 체크박스를 다시 안 헤맨다. 위 표는 이
스크립트의 인자 목록이지 사람이 외울 목록이 아니다.

## 6. 1번 작업은 왕복 시험이다 — 창작이 아니라

**있는 `Walk`를 블렌더에 넣었다가 아무것도 안 고치고 다시 꺼낸다.** 그게 지금 쥐에게
그대로 붙으면 통과.

```
Mouse_Animations.fbx ──import──▶ mouse.blend ──export──▶ CTC_Mouse_Clips.fbx
        │                                                        │
        └────────────── 이 둘이 같은가? ◀───────────────────────┘
```

**왜 창작물로 시작하면 안 되는가**: 새로 만든 동작이 안 움직이면 원인이 둘이다 — 내가
동작을 못 만든 것인가, 파이프라인이 깨진 것인가. **변수를 하나로 묶어야 원인이 보인다.**
`Walk`는 정답을 이미 알고 있는 유일한 입력이다.

### 통과 기준 — 눈으로 보지 않는다

"비슷해 보인다"는 판정이 아니다. 이 프로젝트에는 **에디터 스크립트로 재는** 선례가 있고
(`EarGeometryProbe` · `EyeGeometryProbe`), 같은 방식을 쓴다.

`Tools/CTC/Dev/Probe Clip Parity` — 팩 `Walk`와 왕복한 `Walk`를 받아:

| 무엇을 | 통과 기준 | 이게 잡는 것 |
|---|---|---|
| 커브 **바인딩 집합**(경로 + 프로퍼티) | **완전히 같다** | 위험 1·2·3 전부. 이름이 바뀌거나 한 겹 끼거나 말단 뼈가 늘면 **여기서 먼저 죽는다** |
| 길이·프레임레이트 | 같다 | 샘플링 설정 사고 |
| 본 11개의 로컬 TRS를 **0~1초를 20등분해 샘플** | 각 성분 오차 `< 1e-3` | 축 변환·스케일 사고 |
| `loopTime` | 같다 | 임포트 설정 누락 |

바인딩 집합 비교가 핵심이다 — **값을 재기 전에 이름에서 죽는 것이 정상 경로**이고, 그게
곧 세 위험의 진단명이다.

마지막으로 **눈으로 한 번** 본다: `PlayerMouse` 프리팹에 왕복 클립을 물려 임시 카메라로
렌더한다(씬 뷰 스크린샷은 갱신이 안 붙어 같은 그림을 반복해 준다 — `CLAUDE.md` 기록).
수치가 통과했는데 눈이 이상하면 **재는 방법이 틀린 것**이므로 그때 이 표를 고친다.

## 7. 스크립트로 쓸까, 손으로 찍을까 — 지금 안 정한다

| | 파이썬 | 손 |
|---|---|---|
| git diff | ○ | ✕ (바이너리) |
| 재현 | 명령 한 줄 | 사람이 다시 |
| 타이밍·과장 | 수치를 굴려야 | 더 좋다 |

**`.blend`는 어느 쪽이든 같은 파일이다.** 손으로 만든 것을 나중에 스크립트로 옮기는 건
안 되지만, 스크립트로 만든 것을 열어서 손으로 다듬는 건 된다 — **한쪽만 문이 열려 있다.**

그래서 기본은 **파이썬**이되, 이 결정은 **왕복 시험이 초록이 된 뒤 첫 클립을 만들면서**
내린다. 지금 정하면 해 보지도 않고 정하는 것이다.

**6절의 `export_clips.py`는 이 선택과 무관하다** — 내보내기 설정은 어느 쪽이든 코드다.

## 8. 범위 밖

| | 왜 |
|---|---|
| **어느 테크에 어떤 동작** | 별도 스펙. 파이프라인이 초록이 되기 전엔 정할 값이 없다 |
| 「모션 0」 제약 해제 | 이 문서는 **만들 수 있게** 할 뿐 **만들기로** 정하지 않는다. 클립 추가는 그때 승인받는다 |
| `Shapekey` 레이어 활용 | 기록만 해 둔다 (2절). 블렌더 없이도 되는 일이라 이 문서와 독립이다 |
| 고양이 | 쥐와 절차가 같다. 쥐가 뚫리면 되풀이 |
| 새 메시·새 캐릭터 | 블렌더를 세우는 **이유**지만 지금 할 일은 아니다 |

## 10. 받아들일 위험

| 위험 | 완화 |
|---|---|
| 왕복 시험이 하루 넘게 물린다 | **그 자체가 결론이다** — 그때 유니티 Animation 창으로 돌아간다. 1절이 그 길이 멀쩡하다고 이미 적어 뒀다 |
| 새 클립이 팩과 톤이 안 맞는다 | 0~10프레임 예산(2절)을 지킨다. 첫 클립은 **기존 것 옆에 나란히 렌더**해 비교 |
| 블렌더 의존이 팀에 번진다 | `.blend`가 `Assets/` 밖이라 **FBX만 있으면 프로젝트는 열린다**(4절) |
