# 밸런스 측정용 봇 (2026-08-11)

## 왜

2:8을 기준으로 수치를 다 잡아 놨는데 **한 판도 2:8로 안 돌려 봤다.** MPPM은 최대 4명
(에디터 1 + 클론 3)이고, 로컬 빌드를 붙여도 8명이다 — 10명이 안 된다.

지금까지 검증한 건 **"수치가 제대로 꽂혔는가"**지 **"그래서 5:5인가"**가 아니다.
봇은 그 간극을 메우는 계측기다.

## 범위 — 측정 전용

배포판에 안 들어간다. 개발 빌드에서만 켜지고, 봇이 벽에 부딪혀도 상관없다.
**나중에 '인원 채우기'로 쓰고 싶어지면 같은 뼈대 위에 두뇌만 키운다** — 버리는 작업이 아니다.

봇 승률은 사람 승률이 아니다. 사람은 웅크려 기다리고 미끼를 놓지만 봇은 안 한다.
**구조적으로 불가능한 구간을 걸러내는 도구**지 5:5를 확정해 주진 않는다.

## 대전제 두 개

### ① 봇은 진짜 플레이어 프리팹을 쓴다

별도 오브젝트로 만들면 이속·쿨다운·발소리가 다른 코드를 타서 **측정값이 무의미해진다.**
서버가 `PlayerCat`/`PlayerMouse`를 스폰하고, 사람이 누르는 것과 **같은 입구**에 입력을 넣는다.

그 입구는 이미 있다 — QA 훅이 그대로 봇 API다.

| 훅 | 쓰는 곳 |
|---|---|
| `PlayerMovement.DevMove(worldDir)` | 이동 |
| `CatPounce.DevPounce()` | 덮치기 |
| `MousePopgun` 발사 | 사격 |
| `Sneak.DevSetSneak(bool)` | 잠행 |
| `ShopController` 구매 | 상점 |

서버 스폰이라 `IsOwner`가 서버에서 true다 — 소유자 경로가 그대로 돈다.

### ② 봇은 사람이 아는 것만 안다

서버는 전지적이라 그냥 쥐 좌표를 읽으면 **고양이 봇이 완벽해진다.** 그러면
"발소리 18m가 쓸모 있는가"를 잴 수 없다.

`BotSenses`가 **소리 반경 + 시야**로 걸러야 하고, 그게 곧 계측기다 —
봇이 소리만으로 몇 초 만에 찾는지가 곧 답이다.

## 구조

기능 1개 = 컴포넌트 1개. 순수 로직은 EditMode가 덮는다.

| 컴포넌트 | 하는 일 | 재사용 |
|---|---|---|
| `BotTag` | 이건 봇이다(통계·판정이 본다) | — |
| `BotSenses` | 들리는 것·보이는 것만 좌표로 추린다 | 소리 거리표 · `SightLine` |
| `BotNavigator` | 목표까지 경로 → `PlayerMovement`에 방향 | `NavGraphLogic.FindPathToward` |
| `MouseBotBrain` | 파밍 → 위협 감지 → 도주·잠행 → 상점 | — |
| `CatBotBrain` | 소리 추적 → 추격 → 덮치기 → 강화 구매 | `DogAiLogic` 상태기계 꼴 |
| `BotSenseLogic` | 무엇이 들리는가(순수) | — |
| `MouseBotLogic`·`CatBotLogic` | 상태 전이(순수) | — |

## 손봐야 할 기존 코드

| 곳 | 무엇 | 왜 |
|---|---|---|
| `MatchManager.CountAlive` | `IsPlayerObject` 필터 → 봇도 세기 | 봇은 `SpawnAsPlayerObject`가 아니라 그냥 `Spawn`이다. 지금 그대로면 **8인 판이 성립하지 않는다** |
| `PlayerSpawner` | 봇 N마리 스폰 · 요새 자리 배정 | 사람과 같은 자리 규칙을 써야 스폰 밀도가 같다 |
| `LobbySession` | 봇 수를 들고 있기 | **치즈 총량이 쥐 수에 비례한다** — 봇도 세야 경제가 맞는다 |
| `CheeseSpotDirector` | `MouseCount`에 봇 포함 | 위와 같은 이유 |

## 단계

한 번에 다 하지 않는다. 각 단계가 끝나면 **답이 하나씩 나온다.**

| # | 내용 | 끝나면 알 수 있는 것 |
|---|---|---|
| 1 | 봇 쥐 1마리가 치즈 지점으로 걸어가 판다 + 승패·경제에 포함 | 배선이 맞는가 |
| 2 | `BotSenses` + 고양이 봇(소리 추적 → 덮치기) | **고양이가 소리만으로 찾는 데 몇 초 걸리는가** |
| 3 | 도주·잠행·상점 | 수입 곡선 · 전직 도달 여부 |
| 4 | 배치 러너 — N판 자동 반복 + 통계 CSV | 승률 |

4단계의 러너는 `Time.timeScale`을 올려 판을 빨리 돌린다(720초 × 20판 = 4시간 → 5배면 48분).
봇만 도는 판은 네트워크 지연이 없어 배속이 안전하다.

## 측정 항목

`MatchStatsRecorder`가 이미 판별 기록을 갖고 있다. 여기에 봇 판용으로 더한다.

| 항목 | 기대 |
|---|---|
| 승자 | 2:8에서 5:5 |
| 고양이가 쥐 하나를 찾는 데 걸린 시간 | — (이 값이 소리 밸런스의 답이다) |
| 판당 영구 탈락 쥐 수 | 1~2 |
| 고양이 전직 도달 시각 | 판 막바지(9~11분) |
| 벽 개방 횟수 · 강아지 해방 | 강아지는 3판에 1번쯤 |

## 안 하는 것

- 봇의 협동(고양이 둘이 몰이). 1차에는 각자 논다.
- 봇의 구출·임명. 3단계에서 볼지 정한다.
- 사람다운 은신(웅크려 기다리기, 미끼로 속이기). **이건 B 범위다.**
