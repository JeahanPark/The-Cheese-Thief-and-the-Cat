## 1. 밸런스 계측을 못 믿게 만드는 것

### A1 — 도망치는 쥐가 스스로 잠행한다 (치명)

```csharp
// BotBrainTrees.cs:236-269 — Retreat(). 도주 가지와 반격 가지가 같이 쓴다.
bool seen = _self.Senses.NearestVisible() != null;   // :241
_self.SetSneak(!seen);                               // :242
...
if (seen) { _self.DoDash(); _self.PlaceFortressForFlee(); }   // :265-269
```

호출 사슬을 따라가면:

1. `PlayerMovement.cs:175-180` — 몸은 **이동 방향으로 회전한다**(720°/s). 봇은 카메라가 없으므로 **보는 방향 = 걷는 방향**이다.
2. 도망 = 위협에 등을 돌리는 것. 다음 판단 틱(0.5초)에 고양이는 쥐의 시야각 **55°**(`PlayerInfo.csv`) 밖이다.
3. `BotSenses.NearestVisible()`은 눈으로 잡은 것만 준다(`BotSenses.cs:104-117`). → `seen = false`.
4. 그런데 도주 가지 자체는 계속 돈다 — `ThreatPosition`(`BotBrainTrees.cs:281-293`)이 **소리 단서**(12 m)로 참을 유지한다.
5. 결과: `SetSneak(true)` → `PlayerMovement.cs:168`의 `speed *= SneakSpeedMultiplier(0.45)` → **6.6 → 2.97 m/s**. 고양이는 7.4.

| | 진단서가 잰 값 | 실제로 돌던 값 |
|---|---|---|
| 추격 속도비 | 8.6 / 6.6 = **1.30배** | 7.4 / 2.97 = **2.49배** |
| 20 m 좁히는 시간 | 10초 | **4.5초** |

같은 두 줄이 **대시와 긴급 요새도 잠근다**(`if (seen)`). 사서 안 쓰면 못 산 것과 같다 — 봇 쥐가 도주 수단을 쓰는 창은 **접촉 첫 1틱**뿐이다.

> 이것 하나로 진단서의 관측 넷이 동시에 설명된다: 도주 202회 **탈출 0** · Flee 사망 199/202 · 「도주가 직선이다」 · 「발견 = 사망」.
>
> **§8-2의 「고양이 이속 7.4 → 승률 20%」도 A1이 살아 있는 채로 잰 값이다.** 사람 판 예측의 근거로 쓸 수 없다.

주석의 의도는 *"소리만 들리면 조용히 — 발소리로 위치를 다시 알려 주지 않는다"*였다. 의도는 맞지만 **「쫓기는 중」과 「기척만 느낌」을 `seen` 하나로 구분한 것**이 문제다.

### A2 — 반격 (감사 중 열렸다 · 다만 A1이 대부분 막는다)

감사를 시작할 때는 **`BotAgent.Shoot()`의 호출자가 0건**이었고 트리에 공격 가지가 없었다. 감사 도중 다른 세션이 조건부 반격을 넣었다 — `BotBrainTrees.cs:152-161`(반격 가지) · `BotAgent.CanShootNow/Shoot`(:392-421) · `MouseCombatLogic`(신규, 사거리 85% · 조준 오차 ±7° · 「들켰을 때만」).

남는 문제 둘:

| # | 것 |
|---|---|
| 1 | **조건이 `_catVisible`이다**(`MouseCombatLogic.cs:77`, `CanShootNow`이 `Senses.NearestVisible()`로 채운다). A1 때문에 쥐는 물러서는 순간 고양이를 시야에서 놓친다 → **반격은 접촉당 1~2발**이 한계다. A1을 안 고치면 이 기능의 효과도 못 잰다 |
| 2 | **총 테크는 여전히 안 산다** — `MouseBotLogic.NextPurchase`에 `Gun`·`Pepper`가 없고 EditMode `NextPurchase_NeverBuysGun`이 그걸 고정한다. 즉 반격은 **티어 0 딱총**(피해 5 · 사거리 8 · `WeaponInfo.csv`)으로만 돈다. 공격축 테크(새총 150 · 기관총 600 · 후추 120)는 **계측에 여전히 없다** |

### A3 — 고양이만 스노볼한다 (치명)

```csharp
// MouseBotLogic.NextPurchase :98-147 — 전부 "안 샀으면 산다" 불리언
if (!_hasDash && ...) return TechId.Dash;
if (!_hasFortress && ...) return TechId.Fortress;
... // 5개 다 사면 None
```

```csharp
// BotShopper.BuyForCat :145-152 — 순위표를 훑어 살 수 있는 첫째를 산다
foreach (id in CatBotLogic.PURCHASE_ORDER)
    if (m_Shop.CanBuyNow(id) == TechDeny.None) { m_Shop.Buy(id); return; }
```

`ShopController.Buy` → `m_Slots.ServerApplyNextLevel(id)`(`ShopController.cs:211`) — 즉 **같은 테크를 다시 사면 레벨이 오른다**.

| | 쥐 봇 | 고양이 봇 |
|---|---|---|
| 레벨업 | **안 한다**(불리언 게이트) | **한다** — CatClaw 1→2→3, CatStomp 1→3 … |
| 살 수 있는 것 | Dash·Fortress·Warehouse·CheeseShield·BigPouch = **5개 = 칸 상한 5** | CatClaw·CatStomp·CatHide·CatHunger **×3레벨 = 12회 구매** |
| 도달 상한 | Lv1 5장 | Lv3 4장 (덮치기 +30 · 이속 +0.6 · HP 1450) |
| 빠진 축 | **Attack(총·후추)·Escape(끈끈이)·FastFeet 전부 0** | 광분·예민한 귀만 제외 |

진단서 §5의 「1인 테크 1.46개 = 돈이 없어서」는 절반만 맞다. **돈이 있어도 상한이 5장이고 그중 3축이 구조적으로 비어 있다.** 5축·3레벨이 「장식에 가깝다」고 본 것도 봇이 그 절반을 아예 안 만지기 때문이다.

### A4 — 「봇이 벽에 낀다 → 아니다」의 근거가 쥐를 안 본다 (치명)

```csharp
// TestBotManager.cs:478-497 — 살아 있는 봇만 순회
foreach (BotAgent a in m_Agents) { plans += nav.PlanCount; giveups += nav.GiveUpCount; ... }
```

`Retire()`(:347-380)는 **시야·상점·수입·테크·사망·발사수만** 누적으로 옮기고 **`BotNavigator` 통계는 옮기지 않는다**. 죽은 봇은 `m_Agents`에서 제거된다(Update 루프).

→ 쥐가 전멸한 판에서 `NavStats()`를 부르면 그 줄은 **살아남은 고양이 2마리의 값**이다.
진단서 §2·§6의 *「봇이 벽에 낀다 · 길을 못 찾는다 → 아니다 (giveups 0 · detour 1.00 · stuck 0)」* 는 **쥐 봇에 대해 아무것도 말하지 않는다.**

### A5 — 시야 정직성 통계에 쥐 표본이 섞인다 (높음)

`Retire()`의 시야 이월은 역할을 안 가리고(:350-353 — 주석도 "역할을 안 가린다"), `SightStats()`도 전 봇을 합친다(:432-445). `BotAgent.VisiblePrey()`는 **쥐가 고양이를 본 표본도 똑같이 적립한다**.

→ 진단서 §8-1의 *「봇 고양이는 눈이 정직하다 — 평균 6.4 m · far 1~5%」* 는 **고양이 표본이 아니라 양쪽 합**이다. 쥐는 뒤를 못 봐서(B3) 대개 코앞의 고양이만 잡으므로 평균을 끌어내린다. 결론(눈에 거리 상한이 없다는 원래 우려) 자체는 여전히 유효할 수 있으나, **그 숫자로는 확정 못 한다.**

### A6 — 사인 라벨이 순환논법 (높음)

`m_Deaths.Add($"{LivedSeconds}:{Activity}")`(`TestBotManager.cs:370`). `Activity`는 트리의 잎이 매 틱 덮어쓴다.
위협 가지는 **셀렉터 상단**이다(`BotBrainTrees.cs:166`, 그 위의 반격 가지도 `Activity`를 안 바꾼다) → 고양이를 보거나 12 m 안에서 들은 쥐는 **무조건 `Flee`/`Shelter`**로 라벨이 바뀐다.

| 진단서의 읽기 | 코드가 말하는 것 |
|---|---|
| 「Flee 사망 199/202 = 도주가 실패한다」 | 죽으려면 고양이가 가까워야 하고, 가까우면 라벨은 반드시 Flee다. **동어반복** |
| 「사망 시 `Shop` 0건 = 상점 가다 안 죽는다」 | 상점으로 걷다 걸려도 **죽기 전에 라벨이 Flee로 덮인다**. 「상점 가다 잡힌다」를 이 지표로는 **기각할 수 없다** |

「어디서 지는가」를 라벨로 재려면 **위협 감지 직전의 활동**을 따로 남겨야 한다.

## 2. 고양이 봇 vs 쥐 봇 비대칭

### B1 — 고양이 배회 가지는 도달 불가 (높음)

```csharp
// BotCommander.SearchZones :104-110 — 2초마다 전 고양이에게 Search를 쓴다. 지우지 않는다.
m_Orders.Set(m_Cats[i].Id, new BotOrder(BotOrderId.Search, SearchPointFor(i)));
```

`BotOrders.Clear()`는 `SetCats`(판 시작)와 `Stop()`에서만 불린다. 즉 **판 내내 `Order.HasOrder == true`**.
`BotBrainTrees.cs:103`의 지휘관명령 가지가 항상 성공하므로 **:117 배회 잎은 한 번도 안 돈다.**

→ 진단서 §4의 *「고양이가 배회에 쓴 시간이 0% — 판 내내 단서가 끊기지 않는다」* 는 **오독이다.** 단서와 무관하게 구조적으로 0이다. 「고양이가 너무 잘 찾는다」의 증거로 쓸 수 없다.
(부수: `BotCommander.CountMice()`가 `m_FreeMice`를 세지만 **아무도 안 읽는다** — 지휘관 트리는 잎 하나짜리다.)

### B2 — 청각 비대칭 (높음)

`BotSenseLogic.cs:209-247`.

| | 봇이 들을 수 있는 상대 소리 |
|---|---|
| 고양이 → 쥐 | **14종** — 파밍 `CheeseTick`(32 m) · 창고 `WarehouseTick`(24 m) · 대시 · 설치 · 총 3종 · 피격/사망 · 벽감 2종 · 상자 2종 · 힐 |
| 쥐 → 고양이 | **5종** — `PounceSwing` · `CatHurt` · `CatDeath` · `FortressHit` · `FortressBreak` |

- **고양이는 때리기 시작해야 소리를 낸다.** 접근 전체가 무음이다.
- **`CatSkill`(SfxId 34)·`CatAdvance`(33)가 `IsCatMade`에 빠져 있다.** `SfxPlayer.cs:47-50`은 *"둘 다 **쥐도 들어야 한다** — 큰 효과에 소리를 붙이는 게 스킬을 액티브로 만든 이유다. 모르면 대응할 수 없다"* 고 못박는다. 45 m를 울리는 이 경고가 **봇 쥐에게만 안 들린다.**
- 발소리도 갈린다. 고양이는 조사 중 **잠행**한다(`BotBrainTrees.cs:92`) → 발소리 **4 m**(`PlayerInfo.csv`의 `Cat.SneakFootstepRangeMeters`). 쥐의 소리 위협 반경은 **12 m**(`MouseBotLogic.SOUND_THREAT_RADIUS`). 즉 **접근 중인 고양이는 정의상 쥐 봇의 귀에 안 잡힌다.** 반대로 쥐의 발소리는 22 m를 간다.

### B3 — 쥐 봇은 고개를 못 돌린다 (높음, 사람보다 **덜** 아는 자리)

`PlayerMovement.cs:12-13` 주석: *"몸은 이동 입력이 있을 때만 이동 방향으로 회전한다 — 정지 시 카메라만 도는 '훔쳐보기' 성립."*
**사람은 서서 카메라만 돌려 뒤를 본다. 봇에는 카메라가 없다** — `BotSenses`의 시야 기준은 `m_Self.forward`(몸)다(`BotSenses.cs:122`).

→ 파밍 중(시간의 **51%**) 쥐 봇은 **마지막 걸어온 방향 55°만** 본다. 원의 15%다. 사람 쥐가 상시 하는 「주변 살피기」가 계측에 통째로 없다.

### B4 — 전역 탐색으로 요새를 다 안다 (보통, 사람보다 **더** 아는 자리)

`BotAgent.cs:329, 565` — `Object.FindObjectsByType<FortressShield>`로 **맵 전체의 요새 좌표와 HP**를 매 판단 틱 읽는다. 시야·소리 관문(`BotSenses`)을 안 지난다.

- 쥐 쪽: 본 적 없는 남의 요새로도 피난한다.
- 고양이 쪽이 더 크다 — `ShouldKeepSieging`/`TryGetPreyRefuge`(:308-341)가 **쥐가 어디로 되돌아갈지**를 전역 지식으로 계산해 포위를 유지한다.

주석은 *"화면에 크게 보이는 구조물이라 봇이 아는 게 반칙이 아니다"* 라지만, 미니맵은 `MinimapDiscoverMeters 12`로 **탐색한 곳만** 드러난다(BalanceInfo). 근거가 코드와 안 맞는다.

## 3. 도주 로직 — 정말 직선인가

**꺾기 코드는 있다.** `MouseBotLogic.FleeGoal`(:217-231) — 각도 `{0, 45, -45, 90, -90}`를 순서대로 시험해 **위협에게 안 보이는** 첫 지점을 고른다. EditMode 테스트도 셋 있다(`MouseBotLogicTests.cs:178-213`). 그런데 실제로 안 도는 이유가 셋이다.

| # | 이유 | 근거 |
|---|---|---|
| 1 | **A1이 먼저 죽인다** — 2.97 m/s로는 어느 방향으로 꺾어도 못 산다 | §A1 |
| 2 | 「숨었다」 판정이 너무 헐겁다 (**의심**) | `SightLine.IsBlocked(Vector3,Vector3)`(`SightLine.cs:53-67`)는 **선분에 콜라이더가 하나라도 닿으면 true**다 — Transform 판을 쓰는 `CanSee`와 규칙이 다르다(그쪽은 "가장 가까운 것이 표적이냐"를 본다). 18 m 앞 지점이 선반·벽 **속**이어도 "숨었다"다. `FLEE_ANGLES`는 **0°를 가장 먼저** 시험하므로 어수선한 창고에서는 0°가 거의 항상 통과 → 꺾는 후보에 도달하지 않는다 |
| 3 | **커밋이 없다** | 도주 가지가 매 틱(0.5초) 현재 위치에서 목표를 다시 뽑고, `NavRoute.SetGoal`(:143-157)은 목표가 1.5 m 넘게 움직이면 다시 계획한다(쿨다운 0.25초 < 0.5초). 쥐는 틱마다 3 m 이상 움직이므로 **매 틱 새 직선**이 나온다. 「모퉁이를 돌아 시야를 끊는다」는 여러 틱을 버텨야 성립하는 행동인데 그 상태가 어디에도 안 남는다 |

덧붙여 2번이 통과해 목표가 벽 속이면 `GridPathfinder.TryFindPath`(:121-128)가 최대 12칸(6 m) 옆의 **갈 수 있는 셀**로 스냅한다 — 즉 "숨을 자리"가 벽 **앞면**으로 당겨진다. (의심 — 실행 확인 못 함)

**엄폐물을 끼고 도는 루프·벽감 숨기·요새 문 안팎 카이팅은 코드에 없다.** `BotAgent.IsHiddenFrom`은 위 한 곳에서만 쓰인다.

### C2 — 요새 진입 경주 상수가 낡았다

```csharp
// MouseBotLogic.cs:34-38
/// 고양이는 1.3배 빠르다 — ...
public const float REFUGE_RACE_RATIO = 1.3f;
public const float REFUGE_RACE_MARGIN = 3f;
```

`PlayerInfo.csv`는 이미 고양이 7.4 / 쥐 6.6 = **1.12**다(진단서 §8-2가 내렸다). `ChooseRefuge`(:59-76)는 `theirs <= mine * 1.3 + 3`이면 후보에서 뺀다 → **실제로는 이길 수 있는 요새를 거른다**. 걸러지면 §3의 직선 도주로 떨어진다.
같은 파일 주석의 「고양이 7.8 vs 쥐 6.0」·「잠행 2.7 vs 고양이 7.8」도 낡았다.

## 7. 이 감사가 진단서에 미치는 영향

| 진단서 결론 | 이 감사 뒤의 상태 |
|---|---|
| §1-3 「범인은 추격이다 — 1.30배」 | **수치가 틀렸다.** 실효 2.49배(§A1). 「고양이가 빠르다」가 아니라 「쥐가 스스로 느려진다」 |
| §2 「봇이 벽에 낀다 → ✕」 | **근거 무효**(§A4) — 쥐를 안 본 통계다 |
| §2 「상점 가다 잡힌다 → ✕」 | **근거 무효**(§A6) — 라벨이 Flee로 덮인다 |
| §4 「배회 0% = 단서가 안 끊긴다」 | **오독**(§B1) — 구조적으로 도달 불가한 가지다 |
| §5 「1인 테크 1.46개 = 돈이 없다」 | **절반만 맞다**(§A3) — 상한이 5×Lv1이고 3축이 비어 있다 |
| §6 「봇 고양이가 사람보다 멀리 본다 → 아니다」 | **표본이 섞였다**(§A5). 결론 자체는 남을 수 있으나 이 숫자로는 확정 못 함 |
| §8 「파밍 소리 32→14 효과 0」 | **A1이 있으면 어떤 소리 손잡이도 효과가 0에 가깝다** — 발견 뒤가 이미 결정돼 있다 |
| §8-2 「고양이 7.4 → 승률 20%」 | 변화 자체는 실측이다. 다만 **A1 위에서 잰 값**이라 사람 판·게이트 판정의 근거로는 약하다 |
| §7 손잡이 표(발소리 22→14 · 덮치기 60→34) | **A1을 고친 뒤 다시 재야 한다.** 지금 재면 또 「효과 0」이 나올 가능성이 높다 |

**권고 순서**(고치는 건 이번 작업 범위 밖):

1. **A1** — 도주 중 잠행·대시 게이트를 분리한다(「쫓기는 중」 상태를 몇 초 유지).
2. **A4·A5·A6** — 계측기를 먼저 고친다. 안 고치면 A1을 고쳐도 뭐가 나아졌는지 못 읽는다.
3. **B1** — 배회를 돌리려면 지휘관이 명령을 놓는 조건이 필요하다.
4. **A3** — 쥐 봇에 레벨업·최소 1개의 공격/도주 테크를 준다(진단서 §9-3 #4와 같은 방향).
5. **C1·C2** — 도주 꺾기의 커밋과 낡은 상수. A1을 고친 뒤라야 효과가 보인다.
