# 맵 지오메트리 아트 — 「밤의 식료품 창고」 설계 (2026-08-31)

## 목표

맵의 벽·바닥·복도가 아직 Gridbox 프로토타입(`PROTOTYPE 1×1 METER` 격자)이라
스토어 스크린샷이 막혀 있다. 프롭(요새·창고·상자·벽감)은 이미 절차 메시 + AI 텍스처로
교체됐다 — **프롭을 담는 방을 같은 품질로 끌어올린다.**

롤모델은 R.E.P.O.: 컨셉을 먼저 잡고, 컨셉에 맞는 아트를 구해, 절차적으로 배치한다.

## 확정 결정

| # | 결정 | 내용 |
|---|---|---|
| 1 | 컨셉 | **밤의 식료품 창고·팬트리.** 쥐들이 밤에 숨어들고 집고양이가 지킨다. 인트로 톤(네이비 어둠·앰버 빛웅덩이·치즈 옐로) 유지 — 빛 = 위험. 게임에 이미 '치즈 창고'가 있어 어휘가 이어진다 |
| 2 | 스케일 감각 | **쥐 시점 거대 세계.** 플레이어 크기는 그대로, 세계(선반·궤짝)를 크게 짓는다. 거대함은 넓이가 아니라 **높이·부피**에서 온다 |
| 3 | 최소 넓이 | **대형(120×120, 49방, 치즈 2세트)이 정식 최소.** 기본 30·확장 42는 RoomMapCatalog에서 빼고 개발용으로만 남긴다 |
| 4 | 구조 접근 | **시맨틱 교체.** MapBuilder 레이아웃 두뇌(방·복도·치즈/요새 슬롯·네비그리드)는 그대로, 그리는 어휘만 바꾼다. R.E.P.O.식 완전 방 모듈은 다음 단계 후보 |
| 5 | 아트 소싱 | **보유 팩 주력 + 절차 생성 보완.** `Poly Universal Pack`(polyperfect, 구매 완료)이 가구·소품을 덮고, SdfMesher는 빈 곳만 메운다 |

## 보유 팩 실사 (2026-08-31, unitypackage 목록 스캔)

| 팩 | 쓸 것 | 비고 |
|---|---|---|
| **Poly Universal Pack** (polyperfect, 프리팹 ~5,600) | Farm 궤짝 수십 종 · 배럴 89 · 바구니 58 · Fantasy 선반·체스트·테이블 · Food 거대 견과·과일 · Modular 벽 382 | URP판 동봉. 로우폴리 손그림 톤 — 인트로 톤과 맞음. **전체 임포트 금지, 쓸 카테고리만 선별 임포트** |
| Synty Prototype Pack | 보조 소품 약간(상자·자루·선반) | 본체는 프로토타입 블록 — 지금 Gridbox와 같은 역할이라 테마엔 안 쓴다 |

현대식 주방 가구(냉장고·싱크대)는 두 팩 다 없다 → 컨셉을 팬트리로 반 발짝 튼 이유.
치즈는 자체 절차 메시(`Mesh_CheeseWedge`)가 이미 있다.

## 시맨틱 교체표

콜라이더·네비그리드·치즈/요새 슬롯·수평 밸런스는 **1도 안 움직인다.**
프롭 때와 같은 규칙 — 프리미티브가 치수를 들고, 비주얼은 자식(`PropAssets.AddVisual` 패턴).

| MapBuilder 요소 (지금) | 팬트리 어휘 (바뀔 것) | 높이 |
|---|---|---|
| 지면 Grey1 | 창고 널마루 바닥 | — |
| 경계벽 Grey2 3m | 창고 판벽 + 걸레받이 | 3 → **5m** |
| 방 바닥 Grey4 | 다른 톤 마루·멍석 (존 구분 유지) | — |
| 방 벽 Grey2 3m | **거대 선반·궤짝 더미 벽** — 판벽 백킹 + 팩 프리팹 타일링 | 3 → **5m** |
| 복도 벽 Grey2 1.6m | 크레이트 줄 (넘겨다보이는 성질 유지) | 1.6 → **2.4m** |
| 장애물 Grey box 2.2m | 배럴·밀가루 자루·거대 호박 | 2.2 → **3m** |
| 치즈 등급 원반 빨·주·노 | 기능·색 유지, 접시 위 치즈로 리스킨만 | — |

벽 비주얼 방식: 박스는 트리플래너 판벽 텍스처로 백킹하고, 그 앞에 팩 프리팹(선반·궤짝)을
세그먼트 길이에 맞춰 **타일링해 세운다** — 콜라이더는 여전히 박스 하나다.

## 스케일 승격 + 밸런스 패스

대형(120×120)이 최소가 되므로 메모리 `map-size-double-plan`의 수치표를 태운다 —
**크기만 키우면 반대로 고양이가 아무도 못 잡는다.** 원본은 전부 CSV(코드에 밸런스 0).

| 수치 | 현재 (30×30 기준) | 방향 |
|---|---|---|
| 발소리 가청 (고양이/쥐) | 15m / 8m | 상향 — 단, 4배 선형이 아니라 준선형(맵 절반을 덮으면 은신이 죽는다) |
| 이동속도 (고양이/쥐) | 6.7 / 6.0 | 격차 비율 유지하며 소폭 상향 |
| 매치 시간 | 600s | 이동 비용 증가만큼 상향 |
| 요새 자리·치즈 세트 | 대형 풀에 이미 반영(치즈 2세트·요새 상한 6) | 실플레이로 확인만 |

구체 수치는 구현 단계에서 3인 실플레이로 정한다. `PlayerInfo` 변경 시 씬 재생성 필요.

## UV 해법 — 트리플래너 셰이더

유니티 큐브는 면당 UV 0~1이라 120m 벽에 텍스처가 한 장 늘어난다(함정 5와 같은 계열).
**맵 박스 전용 URP 트리플래너 셰이더**(월드 좌표 미터 투영)로 푼다:

- 박스 크기·분절(벽 세그먼트)과 무관하게 무늬가 이어진다 — 세그먼트 이음새 없음
- `SdfMesher.PlanarUvs`의 "1 UV = 1m 박스 투영" 규약과 같은 결과 — 프롭과 톤 일치
- 프롭·팩 프리팹은 각자 굽힌 UV + 원래 머티리얼 유지 (변경 없음)

## 아트 제작 경로

| 층 | 방식 | 산출물 |
|---|---|---|
| 바닥·벽 텍스처 3~4종 | AI seamless — `텍스처 프롬프트.md`에 프롬프트 추가 | 창고 널마루·판벽+걸레받이·방 바닥 톤 변형 |
| 가구·소품 | **Poly Universal Pack 선별 임포트** — designer 우선순위 트리 2순위(보유 외부 에셋) | 선반·궤짝·배럴·자루·바구니·거대 음식 |
| 빈 곳 메우기 | SdfMesher 절차 생성 | 팩에 없는 것만 (접시 위 치즈 리스킨 등) |

팩 라이선스는 Asset Store 표준(고지 의무 없음)이지만 `3자 에셋 라이선스.md`에 기록한다.
팩 머티리얼은 URP판을 쓰고, 톤이 튀면 틴트만 눌러 맞춘다 — 텍스처 재작업은 안 한다.

## 코드 변경점

| 파일 | 무엇 |
|---|---|
| `SceneComposer.cs` | 재질 배선 Gridbox → 팬트리 머티리얼 교체 (`GridboxMaterial(...)` 6줄) |
| `MapBuilder.cs` | 높이 상수 3종 변경. `AddBox`는 그대로 — 재질이 트리플래너라 메시 손 안 댐 |
| **신규** `MapDresser` (Worker) | 맵 빌드 후 벽 세그먼트에 가구 프리팹 타일링 + 비충돌 소품을 레이아웃 시드로 결정적으로 뿌린다. 네비그리드·콜라이더 무관 |
| **신규** `MapThemeCatalog` (에셋 참조 목록) | 시맨틱 슬롯 → 머티리얼·프리팹 목록. SceneComposer가 굽는다 — 경로 단일 출처(`PropAssets` 패턴) |
| `RoomMapCatalog.cs` | 기본·확장 제외, 대형만 노출 (개발 빌드에선 전부) |
| CSV (`PlayerInfo`·`BalanceInfo`) | 밸런스 패스 수치 |
| `코드 다이어그램.md` | MapDresser·MapThemeCatalog·셰이더 반영 (규칙 8) |

## 단계

1. **팬트리로 보이게** — 트리플래너 셰이더 + 바닥·벽 텍스처 + 재질 교체 + 벽 높이. 스크린샷 가능 시점
2. **대형 승격 + 밸런스** — 카탈로그 정리 + CSV 패스 + 3인 실플레이
3. **가구·소품** — 팩 선별 임포트 + MapDresser 타일링·드레싱
4. **조명 + 촬영** — 달빛(딤 블루) + 앰버 빛웅덩이 연출, 스토어 스크린샷 교체

각 단계가 독립적으로 완결된다 — 1만 끝나도 스크린샷 병목은 풀린다.
