# 맵 생성 시스템 (Map Generation) — 설계 스펙

**작성일:** 2026-07-16 · **상태:** 사용자 승인 (브레인스토밍 완료)
**연관:** [게임 디자인 스펙 §8](2026-07-06-cheese-thief-and-cat-design.md) — 이 스펙과 함께 §8이 방-통로 구조로 개정됨(v3.1)

## 1. 목표

하드코딩된 `BuildGreyboxMap`(가구 박스 15개)을 **에디터 맵 생성 툴**로 대체한다.
생성 대상은 **가구(지형)·치즈지점·요새자리 전부**이며, 결과물은 에셋 라이브러리로 관리한다.

## 2. 맵 패러다임 (기획 변경 — v3.1)

사용자 시안(2026-07-16) 기반. 기존 "개활지 30×30 + 가구 장애물"을 폐기하고 **방-통로 그래프** 구조로 전환:

| 요소 | 정의 |
|------|------|
| **방 (지형)** | 큰 사각 공간 — 치즈지점·요새가 배치되는 생활 공간. 시안의 빨간 박스 (5개 안팎) |
| **통로** | 방과 방을 잇는 좁은 길 — 양측(쥐·고양이) 모두 통과 가능. 시안의 검은 선 |
| **미로 구간** | 통로가 뭉쳐 미로를 이루는 복잡 지대 — 통로 조각의 한 종류 (시안 하단 2곳) |
| **바깥 공간** | 이동 불가 (벽/공백) — 던전식. 동선은 방·통로로만 |

**게임플레이 의도:**
- 통로 = 좁은 길목. 마주치면 회피가 어려워 길목 싸움·추격 리스크가 생긴다
- 방 = 수입(치즈지점)·거점(요새) 공간. 교전과 대치는 주로 방에서
- v3 원칙 유지 — 쥐 전용 지형 없음(통로도 고양이 통과 가능), 안전은 요새가 담당

## 3. 생성 방식 — 후보지 풀 + 랜덤 선택

자유 좌표 절차 생성이 **아니다**. 손으로 검수한 후보 슬롯 풀에서 시드로 뽑는다.

```
MapCandidatePool (후보 풀, level-design 작성)
  ├─ 방 후보: 위치·크기 슬롯 목록
  ├─ 통로 연결 패턴 후보: 어떤 방-방을 잇는지 변형 목록
  ├─ 미로 조각 프리셋: 미리 만든 미로 통로 뭉치들
  ├─ 치즈지점 후보: 방별 슬롯 (등급 규칙 포함)
  └─ 요새자리 후보: 외곽 방들의 슬롯

        │ 시드 입력 → 추출 → 검증
        ▼
MapLayout (확정 결과물, 라이브러리로 다수 저장)
  ├─ 방 목록 (위치·크기)
  ├─ 통로 목록 (경로·폭)
  ├─ 치즈지점 7개 (좌표·등급)
  ├─ 요새자리 6개 (좌표·입구 방향)
  └─ 출처: 시드 번호 or "hand-authored" (사용자 시안)
```

### 고정 규칙 (v3 §12-A 준수)

| 항목 | 값 |
|------|-----|
| 치즈지점 수 | 7개 — 등급 = 중심성. 연결 많고 통로 노출이 큰 방일수록 고등급, 외곽 방은 저등급 |
| 요새자리 수 | 6개 — 외곽 방들에 분산 (한 곳이 뚫려도 피난 가능) |
| QA 앵커 | **G1 치즈지점 + 요새0이 있는 방 1개는 항상 고정 좌표 포함** — MPPM QA 절차 무변경 |
| 통로 폭 | ≥ 고양이 CC 실효 폭 (0.86 + 여유) — 쥐 전용 통로 금지 |

### 생성 후 검증 (자동)

1. **연결성** — 모든 방이 통로로 도달 가능 (고아 방 없음)
2. **겹침 없음** — 방·통로·요새 풋프린트(2.4×2.4)·치즈지점 반경 상호 미침범
3. **통로 폭** — 고양이 통과 가능 확인

## 4. 구성 요소

| 컴포넌트 | 역할 |
|----------|------|
| `MapCandidatePool` (SO) | 후보 슬롯 데이터 — level-design이 작성·소유 |
| `MapLayout` (SO) | 확정 레이아웃 — 생성물·손시안 공용 포맷, 라이브러리로 다수 보관 |
| 생성 툴 (에디터) | `Tools/CTC/Generate Map Layout` — 시드 → 추출 → 검증 → `MapLayout` 저장 |
| 씬 굽기 확장 | `Setup Networking Scene`이 선택된 `MapLayout`을 읽어 지오메트리·치즈지점·요새자리를 씬에 생성 |
| 런타임 데이터화 | `LobbyManager.FORTRESS_SPOTS`·`CHEESE_SPOT_DEFS` 하드코딩 → `MapLayout` 참조로 교체 (스폰 공식 로직은 유지) |

## 5. 사용자 시안 처리

- 사용자가 준 시안(방 5개 + 통로 + 하단 미로 2곳)을 좌표로 옮겨 **`MapLayout` 1호(hand-authored)로 등록**
- 동시에 후보 풀·배치 규칙 추출의 레퍼런스로 level-design에 전달
- 이후에도 사용자 시안은 같은 방식으로 라이브러리에 추가 가능
