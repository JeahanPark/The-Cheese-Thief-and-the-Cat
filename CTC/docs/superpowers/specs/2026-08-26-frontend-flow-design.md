# 프론트엔드 흐름 기획 — 인트로 · 로비 · 대기실 · 인게임 HUD (2026-08-26)

> **무엇을 정한 문서인가**: 임시 IMGUI 접속창을 걷어내고 게임이 시작되기까지의 화면 넷을 세운다.
> 화면 시안(아트보드 6장): https://claude.ai/code/artifact/6ce9e00e-32f8-45e2-a58b-f6df9e45a384
> 참고작: **R.E.P.O.**(대기실의 물성) · **멧챠 카멜레온**(방 목록형 매칭 — 이미 `SteamLobbyManager`가 이 모델) · **리썰 컴퍼니**(상시 표시 최소).
> 밸런스 수치는 **이 문서에서 하나도 바꾸지 않는다.**

---

## 왜 지금인가

접속 화면이 아직 `ConnectionUI.cs`(136줄, `OnGUI`)다. 좌상단 240px 상자에 방 이름 입력칸과 버튼이 세로로
쌓여 있고, 방 목록은 버튼 나열이다. 이건 개발용 발판이지 게임의 첫인상이 아니다. 그리고 **화면 전체가
`Game.unity` 한 씬에 얹혀 있어** 인트로 연출을 넣을 자리가 없다.

## 확정 사항

| # | 결정 | 근거 |
|---|---|---|
| 1 | 씬을 **넷**으로 — `Intro` · `Lobby` · `Room` · `Game` | 네트워크가 붙는 곳은 대기실부터. 그 앞이 오프라인이면 스팀이 흔들려도 게임이 안 죽는다 |
| 2 | **`Game.unity`는 단독 실행을 유지한다** | wesqa·MPPM 회귀가 전부 그 경로다. 씬을 쪼개도 Game에서 플레이를 바로 누르면 지금처럼 돌아야 한다 |
| 3 | 대기실은 **3D 공간** — 쥐 몸으로 돌아다닌다 | 사용자 결정. 방에 들어간 사람이 서로를 본다 |
| 4 | 역할 선택 폐기 → **고양이 1명을 서버가 무작위로 뽑는다** | 사용자 결정. 나머지는 전원 쥐 |
| 5 | 추첨은 **대기실에서 전원에게 공개** (약 4.2초 연출) | 어차피 인게임에서 몸으로 드러난다. 시작 직전이 감정 최고조다 |
| 6 | **밸런스 재조정은 하지 않는다** | 사용자 결정. `CAT_CAPACITY`만 2→1로 내려가고 수치는 그대로 둔다 |

**⚠ 6의 대가를 적어 둔다** — 지금까지의 봇 승률 표는 전부 **2:8(고양이 2)** 기준이다
(`docs/balance/bots_2v8_*.csv`). 고양이가 1명이 되면 그 표는 더 이상 이 게임의 값이 아니다.
다시 재려면 `run_matches.py --cats 1`로 처음부터다. 지금은 사람 플레이테스트가 먼저다.

## 씬 구조

| 씬 | 네트워크 | 무엇을 하는가 |
|---|---|---|
| `Intro.unity` | 없음 | 로고·모델 연출 + 준비 체크(아래). 실패하면 여기서 멈춘다 |
| `Lobby.unity` | 없음 | 공개 방 목록 · 방 만들기 · 우상단 소형 버튼군 |
| `Room.unity` | **NGO 접속** | 3D 대기실. 방장이 맵 선택·시작. 고양이 추첨 연출 |

**스팀 수명은 건드리지 않는다** — `SteamBootstrap`은 `DontDestroyOnLoad`라 씬을 넷으로 쪼개도
연결이 끊기지 않는다. 트랜스포트가 `SteamClient.Shutdown()`을 부르면 안 된다는 08-26 규칙도 그대로다.

## 화면 1 — 인트로

로고와 모델·이펙트 연출이 도는 동안 뒤에서 준비 체크가 끝난다. 체크가 곧 로딩 화면이다.

| 체크 | 실패했을 때 |
|---|---|
| 게임 데이터 (`InfoManager` CSV 4종) | 치명 — 진행 불가, 사유 표시 |
| 개인 설정 (`UserSettings` PlayerPrefs) | 기본값으로 계속 |
| 스팀 연결 (`SteamClient.IsValid`) | 멈추고 "다시 시도" — `SteamBootstrap.TryInit()` |
| 스팀 릴레이 (`RelayNetworkStatus`) | 경고만 — 로비까지는 간다 (혼자 놀 수는 있다) |

- 전부 통과하면 **시작하기** 버튼이 뜬다. 자동 진입이 아니라 한 번 누르게 한다 — 연출을 보고 싶은 사람이 있다.
- 실패 줄은 빨강, 사유 한 줄과 재시도 버튼.
- 우하단에 스팀 연결 상태, 좌하단에 버전·빌드 날짜. **테스터 빌드가 섞이는 사고**가 08-26 함정 목록에 있다 — 버전이 항상 보여야 한다.

## 화면 2 — 로비

| 영역 | 내용 |
|---|---|
| 중앙 | 방 목록 — 방 이름 · 방장 · 맵 · 인원 · 상태. **행을 누르면 우측 상세**로 |
| 우측 | 선택한 방 상세 — 맵 미리보기 · 인원 · 참가자 칩 · **참여하기** |
| 하단 좌 | **방 만들기** (공개 / 친구만) |
| 우상단 | 친구 초대 · 상점(잠김, 자리만) · 설정 · 종료 — 아이콘 38px |
| 좌상단 | 로고 + 내 스팀 프로필 |

- 목록만으로는 뭘 고르는지 모른다. 상세 패널을 거쳐야 **맵과 사람**을 보고 들어간다.
- 방 정원은 **10명**(`SteamLobbyLogic.MAX_PLAYERS`). 가득 찬 방은 회색 + "가득 참".
- 새로고침은 명시 버튼. 자동 폴링은 안 한다 — `OnGUI`에서 스팀을 프레임마다 찔러 터졌던 08-26 사고와 같은 이유다.
  받아온 순간에 라벨을 굳혀 캐시하는 `SteamLobbyLogic.RoomLabel` 방식은 그대로 쓴다.
- 상점은 **자물쇠 아이콘 + "상점 준비 중"** 으로 자리만 잡는다. 눌리지 않는다.

## 화면 3 — 대기실 (3D)

방에 들어오면 쥐 몸으로 선다. 걸어 다니고, 서로가 보이고, 채팅한다.

| 영역 | 내용 |
|---|---|
| 3D | 참가자 전원이 쥐 모델. 머리 위 닉네임 태그. WASD 이동 · Space 점프 |
| 좌상단 | 나가기 · 방 이름 · 공개 여부 · 인원 |
| 좌측 | 참가자 보드 — 아바타 · 닉네임 · 방장 표시 · 빈 자리 |
| 우측 | 맵 선택 — 기본(30×30) · 확장(42×42) · 대형(120×120). **방장만** |
| 우상단 | 친구 초대(스팀 오버레이) · 설정 |
| 좌하단 | 채팅 (`Enter`) |
| 하단 중앙 | **시작** + "고양이 1명은 시작할 때 무작위로 정해집니다" |

- 대기실 몸은 **이동·시점만** 쓴다. 경제·능력·전투 컴포넌트는 안 붙인다 (기능 1개 = 컴포넌트 1개, 규칙 7).
- 사람 입력이 새면 안 되는 곳은 `UiFocus.BlocksGameplay`로 막는다 (BotLab에서 이미 쓰는 패턴).
- 준비(Ready) 체크는 **두지 않는다** — 방장이 시작을 누르는 것으로 끝. 손잡이를 늘릴 이유가 없다.

## 화면 4 — 고양이 추첨

대기실에서 시작을 누르면 그 자리에서 돈다. 씬을 옮기기 **전**이다.

| 시각 | 연출 |
|---|---|
| 0.0s | 암전 — 참가자만 남는다 |
| 0.4s | 스포트라이트가 참가자 사이를 빠르게 돈다 |
| 1.8s | 감속 · 한 명 위에서 정지, 카드가 커진다 |
| 2.6s | 쥐가 고양이 실루엣으로 바뀐다 · 이름 공개 |
| 4.2s | 페이드 → `Game.unity` 로드 |

- **뽑는 것은 서버다.** 클라이언트는 결과를 받아 연출만 재생한다.
- 본인 화면은 문구가 다르다 — "바로 당신" + "쥐들이 창고를 털기 전에 잡아라".
- **직전 판의 고양이는 후보에서 뺀다**(참가자 3명 이상일 때). 연속으로 걸리면 재미가 없다.
- 재시작(`매치 재시작`)마다 다시 뽑는다. 기존 "역할 유지"는 폐기.

## 화면 5 — 인게임 HUD 개선

08-17 개편분을 갈아엎지 않는다. **자리 정리와 임시 UI 제거**가 전부다.

| # | 바꾸는 것 |
|---|---|
| 1 | 타이머 · 남은 쥐 · 고양이 생존을 **상단 중앙 한 덩이**로 묶는다 |
| 2 | 우상단은 내 것만 — HP · 치즈 · 직업. 고양이 HP는 지금처럼 쥐에게 안 보인다 |
| 3 | 좌하단 겹침 정리 — 맵 정보 · 채팅 · 입력 힌트가 한 자리를 다투던 것을 위아래 층으로 |

핫바는 역할별 카탈로그 그대로다 — 쥐 5칸(새총 150 · 기관총 600 · 대시 100 · 요새 80 · 창고 150) ·
고양이 2칸(공격 강화 120 · 이속 강화 90). 수치는 `ShopInfo.csv`가 원본이고 **여기서 안 건드린다**.

## 역할 배정 — 선택제 폐기

지금은 참가자가 쥐/고양이 버튼을 눌러 고른다. 이게 사라진다.

| 대상 | 어떻게 |
|---|---|
| `LobbyUI` 쥐·고양이 버튼 | 삭제 |
| `LobbyController.SelectRole` · `DevSelectMouse` · `DevSelectCat` | 삭제 — 단 QA 우회로는 남긴다(아래) |
| `LobbyRoleLogic.CanSelect` | 삭제 |
| `LobbyRoleLogic.CanStart` | **인원 2명 이상**만 본다 (역할 미선택 검사 제거) |
| `LobbySession.CAT_CAPACITY` | 2 → **1** |
| 새로 만든다 | `CatDrawLogic.Pick(참가자, 직전고양이, 시드)` — 순수 함수, EditMode로 덮는다 |

**⚠ 여기가 가장 위험한 지점이다.** `tools/wesqa/tests/setup_match.py`가 매 판
`TestSelectRoleCat` / `TestSelectRoleMouse`를 부른다. wesqa 스위트 **전부**(v36·v37·v42·v44·v45)가
이 함수를 지난다. 그냥 지우면 QA가 전멸한다.

→ **`TestManager`의 두 훅은 남긴다.** 추첨을 건너뛰고 역할을 강제 지정하는 개발 전용 경로
(`LobbyController.DevForceRole(clientId, role)`)로 다시 배선한다. 게임 흐름에서는 아무도 안 부르고,
`DEVELOPMENT_BUILD`에서만 산다. **`TestManager`는 타입을 쪼개지도, Editor 어셈블리로 옮기지도 않는다**
(리플렉션 진입점이라 옮기면 QA 전멸 — CLAUDE.md 기록).

## 네트워크 흐름

```
Lobby.unity            방 만들기 → SteamLobbyManager.CreateLobby → NGO StartHost → Room.unity 로드
                       방 참여   → JoinLobby → NGO StartClient → 호스트가 Room으로 끌어옴
Room.unity (NGO)       LobbyController가 참가자·맵을 복제. 방장이 시작
                       └ 서버: CatDrawLogic.Pick → 결과를 ClientRpc로 뿌림 → 연출 4.2초
                       └ 서버: NetworkManager.SceneManager.LoadScene("Game")
Game.unity             PlayerSpawner가 배정된 역할로 스폰. 이하 기존 그대로
결과 화면              호스트 Restart → Room.unity으로 복귀(재추첨)
```

- 씬 전환은 **NGO의 `SceneManager`**로만 한다. `UnityEngine.SceneManagement`를 직접 부르면 클라이언트가 따라오지 않는다.
- 대기실에 있는 동안 접속이 끊기면 `Lobby.unity`로 되돌린다 — 사유 토스트 한 줄과 함께.

## 구현 현황 (2026-08-30)

P1과 P2의 앞부분이 끝났다. **인트로 → 로비 → 대기실 → 인게임이 한 줄로 이어진다.**
3인(메인 + MPPM 클론 2)이 대기실에 모여 시작을 누르고, 서버가 고양이를 뽑아 인게임으로 넘기는 것까지
플레이모드에서 실측 확인했다(2026-08-30).

| 화면 | 상태 | 비고 |
|---|---|---|
| 인트로 | ✅ | 스포트라이트 무대 · 메인 메뉴 3줄 · 부팅 체크 4종 · 눈 반짝임 이펙트 |
| 로비 | ✅ | 방 목록 9줄 · 선택 · 상세 · 참여 · 방 만들기 · 새로고침 · 뒤로 · 배경 그림 |
| 대기실 | ✅ | 3D 방 · 참가자 보드 10칸 · 이름표 · 맵 선택(방장) · 채팅 · 옵션(ESC) · 시작 · 나가기 · 고양이 추첨 + **4.2초 연출** + 역할 인계 |
| HUD 정리 | ✅ | 화면 색을 `UiPalette` 한 곳으로 모아 인트로·로비·대기실·인게임이 같은 톤. 인게임 패널 제목도 `CANADIAN MOUSE` |

**기획에서 달라진 것**

| 기획 | 실제 | 왜 |
|---|---|---|
| 인트로에 체크 4종을 **표시** | **표시하지 않음** | 4개 중 유저가 손쓸 수 있는 게 없다. 스팀 출시 뒤엔 "스팀 미실행"이 성립조차 안 한다. 막혔을 때 사유 한 줄만 |
| 스팀 실패는 치명 | **에디터는 검사 안 함 · 개발 빌드는 경고** | 검사하면 개발 중에 인트로를 영영 통과 못 한다(실측) |
| 로비 우상단 아이콘군(친구·상점·설정·종료) | **미구현** | 상점·친구 기능이 아직 없다. 없는 버튼을 그려 두지 않았다 |

## 미결

- 대기실 3D 공간의 **모양** — 어떤 방인가(부엌 구석? 창고?). 지금은 어두운 바닥에 스포트라이트 하나뿐이다. 레벨 디자인 의뢰 대상.
- **대기실에서 시점을 돌릴 수 있어야 하는가.** 지금은 커서를 놓아 UI를 누르게 했고, 그래서 궤도 카메라가 안 돈다(둘 다는 안 된다). 우클릭 드래그로 돌리는 방식이 후보.
- wesqa v36·v37·v38이 `Game.unity` 단독 진입 전제다. 대기실 경로가 생겨도 그 경로는 그대로 살아 있으나(쪽지가 비면 옛 흐름), **재확인은 아직 안 했다.**
- 로비 배경을 정지 이미지로 둘지, 살짝 움직이는 3D로 둘지.
- 상점을 언제 여는가 — 이번 범위 밖. 자리만 잡는다.
