## 0. 무엇이 문제였나

지금 쥐의 구매는 핫바 5칸 위에서 일어난다. 파는 물건은 10종인데 칸은 5개라,
**한 칸이 여러 기술의 후보를 돌려 가며 보여 준다.** 숫자키를 누르면 사지 않고 후보가 넘어가고,
Enter를 따로 눌러야 산다. 그래서:

| 증상 | 원인 |
|---|---|
| 무엇을 파는지, 얼마인지 한눈에 안 보인다 | 10종을 5칸에 접었다 — 한 번에 5개, 그것도 각자 다른 후보만 보인다 |
| 숫자키를 눌렀는데 안 사진다 | 「넘기기 → Enter 확정」 2단계 |
| 같은 숫자키가 상점 안팎에서 다른 뜻이 된다 | 핫바 하나가 「산다」와 「쓴다」를 겸한다 |

**사는 곳과 쓰는 곳이 같은 자리를 쓰는 것이 원인이다.** 이 기획은 그 둘을 분리한다.

## 1. 한 줄

> **상점에 들어가 E를 누르면 파는 물건 열 개가 한 화면에 깔리고, 클릭해서 산다. 핫바는 이제 「쓴다」만 한다.**

## 2. 뒤집는 결정 하나

2026-09-06에 *"3인칭에서 커서가 곧 시야라 커서를 푸는 UI는 쓸 수 없다"*고 정해 팝업을 폐기했다.
이번에 **그 결정을 뒤집는다**(사용자 지시 ③). 대신 커서를 푸는 동안의 위험을 규칙으로 못 박는다(§5).

근거: 상점은 **한자리에 멈춰 서서 하는 일**이고, 그동안에도 발소리·타격음은 그대로 들린다(사용자 지시 ④).
「못 보는 대신 듣는다」가 이 게임의 기본 규칙이라 상점에도 같은 규칙을 적용한다.

## 3. 무엇이 바뀌고 무엇이 그대로인가

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 사는 곳 | 핫바 5칸(후보 넘기기 + Enter) | **상점 팝업**(클릭) |
| 쓰는 곳 | 핫바 — 상점 밖에서만 「쓴다」 | **핫바 — 언제나 「쓴다」** |
| 사는 장소 | 상점 원(반지름 3m) 안 | 그대로 |
| 카탈로그·가격·레벨·칸 5개·품절 2종·되팔기 없음 | | 그대로 |
| 구매음 12m | | 그대로 |
| 고양이 | 핫바 6칸 고정 = 1키 1기술, 늘 「산다」 · 광분은 Space | **그대로** — 상점이 없어 숫자키의 뜻이 하나뿐이라 헷갈릴 자리가 없다 |
| 봇 | `ShopController.Buy`를 직접 부른다 | 그대로 — 팝업은 사람 전용 입구다 |

## 4. 화면

새 화면 하나(`ShopPopup`). 게임 화면 위에 반투명 판을 깔고 그 위에 그린다.

```
┌─ 상점 ───────────────────────── 치즈 420 · 칸 2/5 ─┐
│ 공격   [새총 150]   [후추 탄 120]                   │
│ 방어   [요새 100]   [치즈 방패 100]                 │
│ 자원   [창고 50]    [큰 주머니 120]  [숨은 창고 200]│
│ 도주   [끈끈이 220]                                 │
│ 유틸   [대시 100]   [빠른 발 160]                   │
│                                   E · ESC 닫기      │
└─────────────────────────────────────────────────────┘
```

카드 한 장에 들어가는 것:

| 요소 | 내용 |
|---|---|
| 이름 | 다음 레벨의 이름(`TechInfo.Label`) — 티어마다 이름이 바뀌는 총은 「새총 → 기관총」으로 그대로 보인다 |
| 가격 | 다음 레벨 비용. 만렙이면 「만렙」 |
| 효과 | `TechInfo.Hint` 한 줄 |
| 보유 레벨 | 점 세 개 — 가진 레벨만 채운다 |
| 못 사는 이유 | 흐리게 + 한 줄: 「치즈 80 모자람」 · 「오늘은 품절」 · 「칸이 다 찼다」 · 「깡패는 총을 못 쓴다」 |

**상단**에 내 치즈와 칸 사용량(`2/5`)을 늘 띄운다 — 칸이 이 게임의 진짜 제약인데 지금은 어디에도 안 보인다.

문구는 전부 기존 `TechLogic.DenyText`를 쓴다. **판정 문구의 출처를 늘리지 않는다.**

## 5. 여닫기와 위험

| 상황 | 동작 |
|---|---|
| 열기 | 상점 원 안에서 **E**. 원 밖에서는 아무 일도 안 일어난다 |
| 닫기 | **E** 또는 **ESC** |
| 열려 있는 동안 | 커서가 풀린다. **이동·공격·화면 회전·대시·임명이 멈춘다**(`UiFocus.BlocksGameplay`) |
| 들리는 것 | 발소리·타격음·구매음 전부 그대로 들린다 — 고양이가 오는 것은 알 수 있다 |
| **맞으면** | **즉시 닫힌다.** 커서가 다시 잠기고 조작이 돌아온다 |
| 판이 끝나면 | 닫힌다(결과 패널이 커서를 가져간다) |
| 깡패 변신이 시작되면 | 닫힌다(변신 중에는 모든 조작이 잠긴다) |
| 죽으면 | 닫힌다 |

ESC 우선순위 사슬(`Core/EscapeRouter`)에 끼운다: **설치 취소 → 상점 팝업 → 채팅 → 옵션 닫기 → 옵션 열기.**

상점은 **안전지대가 아니다.** 고양이는 상점 원 안으로 들어와 때릴 수 있고, 구매음 12m는 그대로라
「상점을 지킨다」는 고양이의 전략도 그대로 산다.

## 6. 구조 (CTC 규칙 5·6·7)

| 조각 | 종류 | 책임 |
|---|---|---|
| `ShopPopupLogic` | 순수 static | 카드 한 장의 상태를 정한다: `CardState Of(owned, id, cheese, slotCap, soldOut, role, clubActive)` → {살 수 있음 · 잔액 부족(모자란 양) · 칸 참 · 품절 · 만렙 · 역할 불가}. 열 수 있는가(`CanOpen`)도 여기 |
| `ShopPopup` | View (UI) | 카드를 그린다. 상태를 **조회하지 않는다** — 컨트롤러가 준 목록만 그린다 |
| `ShopPopupController` | Controller | E·ESC 입력, 열고 닫기, 커서·`UiFocus` 토글, 클릭 → `ShopController.Buy(id)` |
| `ShopController` | 기존 | 서버 재검증·지불·적용. **손대지 않는다** |
| `ShopHotbar` | 기존 | 구매 경로를 걷어낸다. 칸 = 보유 기술, 숫자키 = 쓴다 |

- 버튼 구독은 R3(`OnClickAsObservable`), 상태 반영은 구독(`TechSlots.Changed` · 지갑 스트림). `Update` 폴링 금지.
- 클릭은 **로컬에서 막지 않는다** — 못 사는 카드도 눌리면 서버가 거절하고 그 사유가 그대로 뜬다.
  (지금도 `ShopController`가 서버에서 다시 본다. 클라 판정은 표시용일 뿐이다.)

## 7. 핫바 (구매 걷어내기)

- 쥐 핫바 = **보유 기술 목록**. 산 순서대로 채워진다. 빈 칸은 빈 칸으로 둔다.
- 숫자키 = 그 기술을 쓴다. 패시브 칸을 누르면 지금처럼 「패시브 — 늘 켜져 있다」 토스트.
- 「후보 넘기기」·「Enter 확정」·「상점 안이면 산다」는 전부 사라진다. `TechLogic.NextCandidateIndex`도 같이 지운다.
- 상단 모드 문구(`숫자키 = 산다 / 쓴다`)도 사라진다 — 뜻이 하나뿐이라 안내할 게 없다.

## 9. 잘라낸 것

- **키보드 탐색(방향키+Enter)**: 커서를 쓰기로 한 이상 두 입구를 다 만들 이유가 없다. 게임패드를 넣을 때 다시 본다.
- **미리보기·비교 화면**: 카드 한 줄 힌트로 충분하다. 판 중에 읽을 시간이 없다.
- **되팔기·환불**: 배타성이 이 게임 빌드의 핵심이다(2026-09-06 결정 유지).
- **고양이 팝업**: 고양이는 상점이 없어 숫자키가 늘 「산다」 하나다. 바꿀 이유가 없다.

## 11. 화면 개편 — 시안 B「목록 + 상세」 (2026-09-19)

> 발단: 사용자 — *"이거 상점UI 너무 별로야 · 마우스 커서가 위에 올라가면 UI가 바뀌었으면 · ooo은 뭐야?"*,
> *"다른 UI들 디자인 참고해서 만들어야 돼"*. 시안 3개(A 5축 진열장 · B 목록+상세 · C 핫바식 큰 칸) 중 **B**를 골랐다
> (물건이 늘면 목록만 스크롤되고 상세는 그대로라서).

| 부분 | 모양 |
|---|---|
| 창 | 다른 창과 같은 말 — 각진 남색 창 · 위쪽 노란 줄 · 옅은 노랑 제목 · 뒤 화면은 옅은 베일 |
| 머리 | 왼쪽 치즈(노랑 큰 숫자) · 가운데 「상점」 · 오른쪽 칸(노란 칸 = 쓴 칸) |
| 왼쪽 목록 | 축별 머리글(공격·방어·경제·도주·이동) · 한 줄 = 이름 · 단계 막대 3(보유 = 초록) · 값(모자라면 빨강 · 품절 · 만렙) |
| 오른쪽 상세 | **마우스를 올린 줄**의 이름 · Lv · 단계 사다리 3칸(보유 초록 · 다음 노랑 테두리 · 못 사는 다음은 빨강 테두리 · 그 뒤 흐림) · 구매 버튼 · 밑줄 한 줄 |
| 구매 | 줄 클릭 또는 구매 버튼 — 서버가 다시 판정한다(거절 사유는 토스트) |

- **○○○ 점은 없앴다** — 「Lv 1/3」 글자 + 막대로 바꿨다(사용자가 뜻을 못 읽었다).
- 줄은 카탈로그 수만큼 **런타임에 찍는다**(틀만 굽는다) — 기술을 늘려도 창을 다시 짤 필요가 없다. 목록은 스크롤 영역이다.
- 판정·문구는 `ShopPopupLogic`(순수 · EditMode C-41), 마우스 올림 → 상세 배선은 wesqa `qa_v59` ③-b(C-42).
