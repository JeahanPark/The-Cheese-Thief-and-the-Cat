# 2:8 기준 밸런스 · 120×120 대형 맵 (2026-08-10)

## 정한 것

| 구성 | 뜻 |
|---|---|
| **고양이 2 : 쥐 8** | 기준. 여기서 5:5 승률이 되도록 모든 수치를 맞춘다 |
| 고양이 1 : 쥐 6 | 최소 인원. **고양이가 불리한 쪽**으로 남긴다 |
| 맵 120×120 (14400㎡) | 기존 최대(42×42)의 8.2배 |

승리 규칙은 **바꾸지 않았다** — 쥐는 720초를 버티면 이긴다. 대신 고양이를 강화해서 맞췄다.

## 규칙을 유지하면 생기는 구멍과 그 처리

넓은 맵에서 "숨어서 버티면 쥐 승"을 그대로 두면 고양이가 이길 길이 사라진다.
막고 있던 것은 수치가 아니라 **코드 한 줄**이었다.

| # | 문제 | 처리 |
|---|---|---|
| 1 | 웅크리면 발소리가 **완전히** 사라져 구석에 웅크린 쥐는 단서가 0이었다 | 잠행을 '무음'이 아니라 **좁은 반경**으로 (`FootstepLogic.AudibleRange`) |
| 2 | 쥐가 고양이를 **먼저** 들었다(고양이 15m > 쥐 8m) | 뒤집었다 — 쥐 18m · 고양이 12m |
| 3 | 고양이 정원이 1로 박혀 있어 2:N을 만들 수 없었다 | `CAT_CAPACITY` 2 · `MAX_PLAYERS` 10 |
| 4 | 치즈 총량이 고정(4900)이라 8인 판은 1인당 612 — 상점 한 바퀴(1270)도 못 돈다 | 총량 = **쥐 1인당 1400 × 인원** |

## 120×120 맵

손으로 찍은 30×30 풀을 ×4로 늘리면 방 하나가 40×36m짜리 빈 체육관이 된다. 그래서
`LargeMapPoolBuilder`가 **격자에 방을 깔고 통로를 랜덤 신장 트리로 잇는다** — 넓이는
방 개수로 채우고 방 크기는 그대로 둔다.

| 항목 | 값 |
|---|---|
| 격자 | 7×7 = **방 49개**, 칸 간격 17m |
| 방 크기 | 10~12 × 9~11 m (중심 ±0.75 흔들기) |
| 통로 | 랜덤 신장 트리 + 남은 간선의 40% = **62개**, 폭 3.0m |
| 치즈 지점 | **14개** (등급 1~7을 **2벌**) |
| 요새 | **8개** (쥐 최대 8) — 바깥 테두리에 고르게 |
| 벽감 · 감옥 | 6 · 3 (방 수에 비례) |
| 벽 뒤 상자 | 5 — 깡패권 1 · 영웅권 1 · 치즈 3 |

**치즈를 2벌 깐 이유**: 7지점만 두면 인원 비례로 커진 총량이 지점당으로 몰려
낮은 등급 자리가 판이 끝날 때까지 안 마른다 — 그러면 고갈로 만드는 후반 압축이 사라진다.
14지점이면 7등급 자리가 약 85초에 마른다(판의 1/8).

**중앙 칸은 흔들지 않는다** — (0,0)이 고양이 스폰 자리라 벽 안에서 시작하면 안 된다.

### 고양이 전직이 안 열리던 문제

고양이 수입은 덮치기 하나뿐이다 — 쥐(100HP)를 잡으면 `100/2 + 킬 보너스`.
전직은 강화 두 줄 만렙이라 **1750**이 필요했고, 그건 **16번 잡아야** 하는 값이다.
720초 · 120×120 · 고양이 둘(킬을 나눠 갖는다)에서는 한 번도 안 열린다.

강화 가격을 40% 내려 **1050**으로 만들었다. 스택당 효과는 그대로라 **최종 파워는 같고
도달만 빨라진다** — 7~8번 잡으면 판 막바지에 열린다.

`ShopLogicTests.Balance_CatAdvancementIsReachableWithinOneMatch`가 이 관계를 잠근다
(5~10킬 사이). 가격이나 킬 보너스를 만질 때마다 조용히 다시 막히는 걸 여기서 잡는다.

## 벽은 막고 있을 뿐이다 (2026-08-11)

벽감이 **보상을 품는 것**에서 **막고 있는 것**으로 바뀌었다.

```
전                              후
──────────────────────────      ────────────────────────────────────
[벽] ──부수면──> 치즈           [벽] ──부수면──> [상자] ──부수면──> 보상
[벽] ──부수면──> 강아지 소환    [벽] ──부수면──> 길이 열림 ──> 강아지가 나온다
```

**왜** — 벽이 곧 치즈면 부순 사람이 19초간 소리를 다 내고도 늦게 온 사람에게 뺏긴다.
두 단계면 벽을 연 뒤에도 시간이 더 들어 **그 자리에서 붙는다**. 벽감의 원래 의도가 경쟁 유발이었다.

| 항목 | 결정 |
|---|---|
| 상자 자리 | **전부 벽 뒤**. 바닥에 놓는 상자는 0개 |
| 직업권 | **벽 뒤에만.** 바닥에 굴러다니면 판을 뒤집는 물건이 아무 소리 없이 손에 들어간다 |
| 깡패권·영웅권 | 서로 **가장 먼 두 벽**에 나눠 둔다 — 나란히 두면 한 사람이 둘 다 먹는다 |
| 벽감 수 하한 | 3 → **4**. 강아지 1 + 직업권 2를 빼고도 치즈 벽이 하나는 남아야 한다 |
| 상자 덩이 수 | 2 → **3**. 벽 뒤 상자가 유일한 경쟁 지점이 됐다 |

사라진 축: "조용히 혼자 찾는 상자". 이제 상자는 전부 시끄럽고 경쟁하는 물건이다 —
넓은 맵에서 조용한 보상은 그냥 못 찾는 보상이 된다.

죽은 데이터 둘을 CSV에서 뺐다(`AlcoveDropCount`·`AlcoveDropScatterMeters`) — 벽이 더는
직접 흩뿌리지 않는다.

## 잡은 버그

| 증상 | 진짜 원인 |
|---|---|
| 대형 맵에서 지점 매장량이 0 | 총량만 인원 비례로 줄고 벽감·상자는 절대량이었다 → 하한 도입 |
| 강아지가 Chase 상태로 **굳는다** | 표적이 그래프의 다른 조각에 있으면 `FindPath`가 빈 목록을 준다. 감지 반경 14→20이 이걸 드러냈다 → `FindPathToward`가 갈 수 있는 곳 중 표적에 가장 가까운 자리로 보내고, 그것도 없으면 표적 쪽으로 그냥 민다 |
| 벽감 6개가 **맨 아래 한 줄에 전부** 몰린다 | 방 목록 앞에서부터 N개를 집었다. 격자 맵은 그 순서가 한 줄씩이다 → `PlacementLogic.SpreadPick`(farthest-point sampling), 중앙에서 시작해 강아지 벽감이 한가운데 놓이게 |
| 감옥 3개가 **요새와 같은 좌표** | 감옥이 쥐 스폰 위에 서고, 그 앞을 지키는 고양이가 스폰까지 같이 지킨다 → 요새 방 제외. 단 후보가 감옥 수의 2배 미만이면 제외하지 않는다(기본 맵은 방 6개 중 4개가 요새 방이라, 무조건 빼면 감옥 둘이 10m로 붙는다) |

그래프는 벽을 지나는 간선을 걷어내면 조각난다(기본 맵 실측 39노드 29간선 — 이어져 있으려면
최소 38개). 이건 남은 구조적 한계다. 지금은 강아지가 굳지 않게만 막아 뒀다.

## UI (2026-08-10)

밸런스를 바꾸면 화면도 같이 바뀌어야 하는데, 직업·2단계는 **화면에 아무 표시가 없었다**.

| 만든 것 | 왜 |
|---|---|
| `TimerHud`가 2단계 시계를 본다 | 4분을 줬는데 1단계 시계만 보고 있어 0:00이 박힌 채였다 |
| `MouseJobHud` — 내 직업 + 지금의 승리 조건 | **부하는 거절을 못 한다.** 승리 조건이 바뀌는데 본인이 몰랐다 |
| `JobBadge` — 머리 위 편 표식(쥐에게만) | 2단계는 쥐끼리 편이 갈리는데 누굴 쏠지 알 수가 없었다 |
| 조작 안내 수정 + F키 | "살금살금(**무음**)"이 거짓이 됐다. 임명 조작은 어디에도 없었다 |

**표식은 고양이에게 안 보인다** — 보스를 알아보면 우선 사냥으로 2단계 자체를 없앨 수 있다.

### 여기서 나온 버그

떴다(v3.9에서 `GangWin`을 추가할 때 놓친 자리). 승자가 셋인 게임이다 —
`ResultLabelTests`가 결과 하나하나에 고유한 문구가 있는지 잠근다.
