# 코드 전면 재편 계획

> **실행 시점**: 빌드 배포 → 플레이테스트 → 기획 수정 → **1차 최종본 완료 후**.
> 그 전까지는 착수하지 않는다. 이 문서는 그때 5분 만에 맥락을 되찾기 위한 것.
> 작성 2026-07-28 · 조사 기준 커밋 `ab94084`

---

## 왜 하는가

기능을 빠르게 쌓느라 규약과 구조가 밀렸다. 지금 상태로 더 쌓으면 "어디에 뭘 넣어야 하는지"를
매번 다시 정해야 한다. 기획이 확정되는 1차 최종본 직후가 손대기 가장 싼 시점이다.

## 현황 (조사 결과)

| 항목 | 실태 |
|---|---|
| 네이밍 | `m_` 46파일 vs 무접두·`_camel` 21곳 혼재 (`catPrefab`, `moveSpeed`, `_cam`, `_players`…) |
| 죽은 코드 | 빈 디렉터리 7개(Cat·Mouse·Data·Items·Stealth·UI·Utils), `GameController`·`NetworkGameController` 참조 0, `ResourceManager`·`GameSceneManager` 참조 0 |
| 중복 | `AudioManager`(사실상 미사용) vs `Audio/` 7개 플레이어, `Singleton`+`MonoSingleton` 두 벌, `DevMppmMenu`+`MppmSetupMenu` |
| God object | `SetupNetworkingScene` **1072줄/25메서드**, `TestManager` **464줄** |
| 아키텍처 | Manager/Controller/Worker/Component 규약이 있으나 **Controller 계층이 비어 있고** `LobbyManager`가 세션·스폰·맵지휘·UI연결을 겸한다 |

**잘 되어 있는 것** — 순수 로직 분리(`*Logic` 12종) + EditMode 137개, 어셈블리 4분할,
그리고 **씬·프리팹이 전부 `SetupNetworkingScene`의 산출물**이라는 점.

마지막이 이 재편을 안전하게 만든다. `[SerializeField]` 필드를 리네임해도 **씬 재생성으로 배선이 복구**된다.
수작업 배치가 없어 참조가 깨질 위험이 낮다 — 그래서 지금까지 미뤄둔 일괄 리네임이 가능해졌다.

## 원칙

1. **동작 불변.** 기능 추가·수치 변경을 섞지 않는다.
2. **단계마다 검증.** EditMode 137 + wesqa QA 51항목 회귀. 깨지면 그 단계에서 멈춘다.
3. **단계별 커밋.** 되돌릴 수 있어야 한다.
4. 순수 로직(`*Logic`)은 이미 규약을 지키고 테스트가 붙어 있다 — **건드리지 않는다.**

## 단계

### 1. 죽은 코드·중복 제거

삭제 대상 (전부 참조 0 재확인 후):

| 대상 | 사유 |
|---|---|
| `Cat/ Mouse/ Data/ Items/ Stealth/ UI/ Utils/` | 빈 디렉터리 (WES 이식 흔적) |
| `Controller/GameController.cs`·`NetworkGameController.cs` | 참조 0 |
| `Managers/ResourceManager.cs`·`GameSceneManager.cs` | 참조 0 |
| `Core/Singleton.cs` | `MonoSingleton`만 사용 |
| `Managers/AudioManager.cs`·`AudioKey.cs` | 실제 오디오는 `Audio/SfxPlayer`·`BgmPlayer`가 담당 |
| `Editor/DevMppmMenu.cs` | `MppmSetupMenu`가 대체 (리플렉션 탐사용 임시 도구였음) |

`Core/Managers.cs`의 죽은 프로퍼티(`Resource`/`Scene`/`Audio`)와 주석 처리된 `PopupManager`·`InputManager`도 정리.

### 2. 네이밍·레이아웃 통일

`*Logic`·`MapData` 계열 직렬화 struct는 제외한다 — **데이터 DTO의 public 필드는 규약 예외**.

| 현재 | 목표 | 대표 위치 |
|---|---|---|
| `[SerializeField] private T name;` | `m_Name` | `LobbyManager.catPrefab`, `PlayerMovement.moveSpeed`, `LobbyUI`(8), `OrbitCameraController`(3), `PlayerAnimationDriver`(4), `PlayerCameraBinder`(2) |
| `private T _name;` | `m_Name` | `OrbitCameraController._cam/_orbital/_angles`, `LobbyManager._players/_gameStarted`, `PlayerMovement._controller/_verticalVelocity` |
| `IEnumerator Start()` | `Start()` + `StartCoroutine(CoStart())` | `Network/MppmAutoConnect.cs` |
| 클래스 레이아웃 | const → static readonly → SerializeField → private → 라이프사이클 → public → private | 전 파일 |

> 리네임 시 **생성기의 문자열 인자**(`SetRef(x, "catPrefab", …)`)도 함께 고치고,
> `Tools/CTC/Setup Networking Scene`을 반드시 재실행한다.

### 3. 아키텍처 재배치

| 계층 | 정의 | CTC 배치 |
|---|---|---|
| **Manager** | 씬 전환에도 유지되는 글로벌 싱글톤 | `ChatManager`만. CTC는 단일 씬이라 그 외 글로벌은 불필요 |
| **Controller** | 씬 흐름 관리 | **신설** — `LobbyController` |
| **Worker** | 씬 내 기능 단위 | `MapBuilder`, `CheeseSpotDirector`, `SfxPlayer`, `BgmPlayer`, `MatchStatsRecorder`, `OccluderFader`, `PlayerSpawner`(신설), `MapDirector`(신설) |
| **Component** | GameObject 부착 단일 책임 | `Health`, `RoleTag`, `CatPounce`, `MousePopgun`, `PlayerMovement`, `CheeseWallet`, `ShopController`, `CheeseSpot` … |

핵심은 **`LobbyManager`(290줄) 분해**다. 지금 네 가지를 동시에 한다:

| 쪼갤 것 | 새 위치 | 책임 |
|---|---|---|
| 참가자 목록·역할·시작 상태 | `Lobby/LobbySession.cs` (NetworkBehaviour) | 네트워크 상태만 소유 |
| 역할 선택·시작 RPC, UI 연결 | `Lobby/LobbyController.cs` | 씬 흐름 |
| `SpawnPosition`·`SpawnPlayers`·시드머니 | `Lobby/PlayerSpawner.cs` | 스폰. 순수 공식 `SpawnPosition`은 static 유지(테스트가 직접 호출) |
| 맵 인덱스·`RebuildMap` | `Map/MapDirector.cs` | 맵 선택·재구축, `CheeseSpotDirector.Rebind` 호출 |

이름 자체도 규약 위반이다 — Manager는 글로벌 싱글톤인데 `LobbyManager`는 씬 오브젝트다.

### 5. 폴더·어셈블리 정리

- `Testing/`은 전체가 `#if UNITY_EDITOR`인데 `CTC.Runtime` 안에 있다 →
  `CTC.Testing.asmdef`(Editor 플랫폼 전용)로 분리. 런타임 어셈블리에서 QA 코드가 빠진다.
- `CTC.Runtime` 자체 분할은 **하지 않는다** — 순환 참조 위험 대비 이득이 작다.
- 빈 `Tests/PlayMode/` 처리 결정.

### 6. 에이전트·규약 문서 배선 수정 → **선행 완료 (2026-07-28)**

## 검증 (각 단계 끝마다)

1. `u_editor_asset(refresh)` → 컴파일 에러 0
2. `Tools/CTC/Setup Networking Scene` 재생성 (2·3·4단계 필수 — 씬 배선이 바뀐다)
3. `Tools/CTC/Run EditMode Tests` — **137/137 유지**
4. MPPM 3인 + wesqa `full_qa2.py` — **51/51 유지** (맵 선택 7 + 두 맵 각 22)
5. 3·4단계 후 스크린샷 육안 비교 — 로비 패널·핫바·치즈 라벨

EditMode는 순수 로직만 덮는다. MonoBehaviour 재배치의 실질 안전망은 **wesqa 51항목**이므로,
3·4단계는 QA를 돌리기 전에 커밋하지 않는다.

## 커밋 단위와 위험도

| 커밋 | 단계 | 위험 |
|---|---|---|
| 1 | 죽은 코드·중복 제거 | 낮음 |
| 2 | 네이밍·레이아웃 + 씬 재생성 | 낮음 (기계적, 생성기가 배선 복구) |
| 3 | `LobbyManager` 분해 | **높음** — 네트워크 상태 소유가 옮겨진다 |
| 4 | 에디터 God object 분해 | 중간 (에디터 전용, 런타임 영향 없음) |

3단계가 가장 위험하다. 깨지면 로비 진입 자체가 안 되므로 앞 두 커밋을 안정화한 뒤 착수한다.
