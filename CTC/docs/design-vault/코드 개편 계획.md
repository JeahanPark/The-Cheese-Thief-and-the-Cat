## 왜 하는가

기능을 빠르게 쌓느라 규약과 구조가 밀렸다. 지금 상태로 더 쌓으면 "어디에 뭘 넣어야 하는지"를
매번 다시 정해야 한다. 기획이 확정되는 1차 최종본 직후가 손대기 가장 싼 시점이다.

## 현황 (조사 결과)

| 항목 | 실태 |
|---|---|
| 네이밍 | `m_` 46파일 vs 무접두·`_camel` 21곳 혼재 (`catPrefab`, `moveSpeed`, `_cam`, `_players`…) |
| 죽은 코드 | 빈 디렉터리 7개(Cat·Mouse·Data·Items·Stealth·UI·Utils), `GameController`·`NetworkGameController` 참조 0, `ResourceManager`·`GameSceneManager` 참조 0 |
| 중복 | `AudioManager`(사실상 미사용) vs `Audio/` 7개 플레이어, `Singleton`+`MonoSingleton` 두 벌, `DevMppmMenu`+`MppmSetupMenu` |
| God object | `SetupNetworkingScene` **1190줄**, `TestManager` **595줄** |
| 아키텍처 | Manager/Controller/Worker/Component 규약이 있으나 **Controller 계층이 비어 있고** `LobbyController`가 세션·스폰·맵지휘·UI연결을 겸한다 |
| **UI** | HUD 8개가 전부 `Update()` 폴링 — 매 프레임 `GetLocalPlayerObject` 재탐색 + 문자열 재조립. MVC 분리 없음(View가 조회·판정까지) |
| **비동기·이벤트** | 코루틴 5곳(`HitFeedback`·`MppmAutoConnect`×2·`TestManager`×3), 버튼 6곳이 `onClick.AddListener` 람다 |

**잘 되어 있는 것** — 순수 로직 분리(`*Logic` 12종) + EditMode 141개, 어셈블리 4분할,
wesqa 실플레이 QA 14항목, 그리고 **씬·프리팹이 전부 `SetupNetworkingScene`의 산출물**이라는 점.

마지막이 이 재편을 안전하게 만든다. `[SerializeField]` 필드를 리네임해도 **씬 재생성으로 배선이 복구**된다.
수작업 배치가 없어 참조가 깨질 위험이 낮다 — 그래서 지금까지 미뤄둔 일괄 리네임이 가능해졌다.

## 원칙

1. **동작 불변.** 기능 추가·수치 변경을 섞지 않는다.
2. **단계마다 검증.** EditMode **141** + wesqa **14항목**(`tools/wesqa/tests/qa_v36.py`) 회귀. 깨지면 그 단계에서 멈춘다.
3. **단계별 커밋.** 되돌릴 수 있어야 한다.
4. 순수 로직(`*Logic`)은 이미 규약을 지키고 테스트가 붙어 있다 — **건드리지 않는다.**
5. **단계마다 [[코드 다이어그램]] 갱신** — 클래스·워크플로우 머메이드가 개편 후 구조와 맞아야 한다(CTC 규칙 8).

4. MPPM 3인 + `tools/wesqa/tests/qa_v36.py` — **14/14 유지**
5. 3·3b·4단계 후 스크린샷 육안 비교 — 로비 패널·핫바·치즈 라벨
6. [[코드 다이어그램]] 머메이드 갱신

EditMode는 순수 로직만 덮는다. MonoBehaviour 재배치의 실질 안전망은 **wesqa 14항목**이므로,
3·3b·4단계는 QA를 돌리기 전에 커밋하지 않는다.

## 커밋 단위와 위험도

| 커밋 | 단계 | 위험 |
|---|---|---|
| 1 | 죽은 코드·중복 제거 | 낮음 |
| 2 | 네이밍 + 코루틴→UniTask + 버튼→R3 + 씬 재생성 | 낮음 (기계적, 생성기가 배선 복구) |
| 3 | `LobbyController` 분해 | **높음** — 네트워크 상태 소유가 옮겨진다 |
| 3b | UI MVC + R3 구독 (브리지 2개 → View 8개) | **높음** — 화면이 안 뜨면 즉시 드러나지만 조건 분기(관전자·시작 전)가 미묘 |
| 4 | 에디터 God object 분해 | 중간 (에디터 전용, 런타임 영향 없음) |
| 5 | `TestManager` partial + Testing asmdef | 중간 (wesqa 리플렉션 경로 확인 필요) |

3·3b가 가장 위험하다. 깨지면 로비 진입·HUD가 통째로 안 뜨므로 앞 두 커밋을 안정화한 뒤 착수한다.
3b는 브리지 2개를 먼저 넣고 **View를 하나씩** 전환한다 — 8개를 한 커밋에 몰면 원인 추적이 불가능해진다.
