# Gemini 타일러블 텍스처 생성 프롬프트 시트 (v1)

직접 구운 프롭 메시(`Assets/Scripts/Editor/SdfMesher.cs`)에 씌울 알베도 텍스처 6종.
**지금 만드는 것은 3종**(치즈·벽돌·나무)이고, 나머지 3종(티켓 2·대기실 바닥)은 프롬프트만 남긴 보류다 —
직업권은 0.35m 카드라 텍스처가 화면에서 안 보이고, 대기실 바닥은 어차피 어둡다.
[사운드 프롬프트.md](사운드%20프롬프트.md)와 같은 용도의 문서다 — **자동화가 실패해도 이 문서를
Gemini 웹에 그대로 붙여넣으면 같은 결과를 다시 뽑을 수 있다.**

## 기술 제약 (프롬프트가 이렇게 생긴 이유)

| 제약 | 근거 | 프롬프트에 미친 영향 |
|---|---|---|
| **1 UV = 1 미터** | `SdfMesher.PlanarUvs`가 정점 좌표를 그대로 UV로 쓴다 | 무늬 한 칸의 크기를 "이미지의 몇 %"가 아니라 **실제 센티미터**로 지정한다 |
| **완전 seamless 필수** | 텍스처가 1m마다 반복된다. 이음새가 있으면 1m 격자가 드러난다 | 모든 프롬프트에 상·하/좌·우 가장자리 일치 요구 |
| **박스 투영(3축)** | 법선이 가장 향하는 축을 뺀 두 축을 UV로 쓴다 | 면마다 UV 축이 달라진다 → **등방성 무늬**. 방향성이 불가피한 것(벽돌·널)은 결을 약하게 |
| **평평한 알베도** | 조명은 URP가 준다 | 그림자·하이라이트·AO·베벨을 굽지 않는다. 저대비 |
| **작은 프롭은 텍스처를 크롭한다** | 티켓은 약 0.3m → 텍스처의 30%만 보인다 | 티켓은 **큰 무늬 금지**, 균질한 미세 결만 |

## 공통 접두 (그대로 복사해 앞에 붙인다)

```
Create a seamless tileable texture map. 1024x1024 square, perfectly flat top-down
orthographic view of a surface, filling the entire frame edge to edge. Style:
hand-painted stylized low-poly game texture, cute cartoon look, flat albedo/diffuse
only. NO baked lighting: no drop shadows, no specular highlights, no ambient
occlusion, no vignette, no bevel, no 3D relief. Even flat illumination, low contrast,
soft muted color variation only. The pattern must tile perfectly — the left edge
continues into the right edge and the top edge continues into the bottom edge, with
no visible seam. No border, no frame, no background, no perspective, no objects,
no text, no letters, no logo, no watermark, no signature, no humans.
```

## 재생성 방법

1. Gemini 웹(<https://gemini.google.com/app>) 새 채팅 → **공통 접두 + 해당 행 프롬프트**를 한 메시지로 붙여넣는다.
2. 결과가 아래 검수 기준에 걸리면 같은 채팅에서 **어긋난 항목만 지적해 수정 요청**한다
   (예: "the seam on the right edge doesn't match the left, redo it fully tileable").
3. 최대 5회까지 재시도. 그래도 안 되면 그 항목만 보류하고 단색 머티리얼을 유지한다.
4. 원본 크기로 다운로드 → 아래 경로에 파일명 그대로 저장.

| 파일 | 경로 |
|---|---|
| `T_CheeseWall` · `T_BrickWall` · `T_WoodCrate` · `T_PaperHero` · `T_PaperGang` | `Assets/Materials/Props/Textures/` |
| `T_RoomFloor` | `Assets/Materials/Room/Textures/` |

## 검수 기준 (통과 못 하면 재생성)

| # | 항목 | 방법 |
|---|---|---|
| 1 | **타일링 이음새 없음** | 이미지를 2×2로 이어 붙여 중앙 십자선이 보이는지 본다. 보이면 실패 |
| 2 | 글자·워터마크·서명·사람 0 | 확대해 모서리까지 확인 |
| 3 | 베이크된 그림자·하이라이트 없음 | 밝기 히스토그램이 한쪽으로 몰리지 않고, 큰 명암 그라데이션이 없어야 한다 |
| 4 | 해상도 1024×1024 정사각, 알파 없음 | 다르면 리샘플 |
| 5 | 무늬 크기가 지정한 센티미터대 | 1m 안에 들어갈 개수가 맞는지 센다 (벽돌 4~5열, 널 5~6장 등) |
| 6 | 방향성 과함 없음 | 90° 돌려 봐도 어색하지 않은가 (벽돌·널은 예외로 허용하되 결이 약해야 한다) |

## 머티리얼 배선 시 주의

URP Lit은 **Base Map × Base Color**로 곱해진다. 지금 머티리얼들은 색이 들어가 있어
텍스처를 그대로 꽂으면 두 번 어두워진다. 맵을 물릴 때 **Base Color를 흰색으로 되돌리거나**
아주 옅은 틴트만 남긴다. 단, `M_Cheese`(밝은 치즈)와 `M_CheeseWall`(어두운 치즈)은
**같은 `T_CheeseWall`을 공유하고 Base Color 틴트로만 구분**하는 것이 의도다.

Tiling/Offset은 건드리지 않는다 — UV가 이미 미터 단위라 `1,1`이 곧 1m다.

## 임포트 설정 (권장)

| 항목 | 값 | 이유 |
|---|---|---|
| Texture Type | Default | 스프라이트가 아니다 |
| sRGB (Color Texture) | 체크 | 알베도다 |
| Alpha Source | None | 알파 없음 |
| Wrap Mode | **Repeat** | 1m마다 반복이 전제다. Clamp면 프롭 전체가 늘어난다 |
| Filter Mode | Bilinear | Trilinear은 밉 전환이 흐려진다 |
| Aniso Level | 4 (바닥은 8) | 비스듬히 보는 바닥의 선명도 |
| Mip Maps | 켬 | 멀리서 지글거리지 않게 |
| Max Size | 1024 | 원본 그대로 |
| Compression | Normal Quality (DXT1/BC1) | 알파가 없다 |

## Gemini 결과물 후처리 (실제로 필요했던 것)

Gemini 웹 출력은 **그대로 쓸 수 없다.** 세 장 모두 아래 처리를 거쳤다.

| # | 문제 | 처리 |
|---|---|---|
| 1 | 출력이 2048×2048 RGBA | 1024×1024 RGB로 리샘플 |
| 2 | **반짝이 워터마크(✦)가 우하단에 항상 박힌다** | 그 자리를 같은 이미지의 깨끗한 패치로 `cv2.seamlessClone`. 나무는 **같은 널(같은 y)** 에서 패치를 떠야 판자 경계선이 안 끊긴다 |
| 3 | 가장자리가 미세하게 안 맞음(1m마다 줄이 보임) | 위/아래·좌/우 차이를 저주파 코사인 램프로 내부에 흘려 상쇄(σ≈16). σ가 작으면 **세로 줄무늬**가 생기니 키워야 한다 |
| 4 | 벽돌이 요구의 3배로 잘게 나옴(가로 13장). 두 번 요청해도 안 고쳐짐 | 프롬프트 재시도 대신 **주기 단위 크롭**: 벽돌 폭 256px·행 높이 128px을 검출해 (129,128)에서 1024×1024를 잘라냈다 → 가로 4장·세로 8행. 주기 경계에서 자르므로 타일링이 유지된다 |
